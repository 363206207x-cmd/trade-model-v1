## 3. Watchlist Pool Proof Sources

Before any future market-read work, Watchlist Pool membership must be proven by a source that is explicitly authorized for that purpose.

Potential future proof sources may include:

- a canonical Watchlist Pool membership source or read model authorized by a later PR;
- a DB-backed Watchlist Pool membership read only after a separate DB read / mapper / repository authorization gate passes;
- a reviewed watchlist config snapshot with version, timestamp, and owner;
- a test fixture in a test-only package, only for targeted tests and never as production eligibility proof.

Every proof source must identify the symbol, membership state, proof source, watchlist config version, proof timestamp, stale/missing behavior, and source ownership.

Display Slots / 默认六币 cannot prove scan eligibility and cannot become scan universe or batch universe. Watchlist Pool remains the scan candidate boundary.

## 4. Future Real Scan Input Assembly Gate

Future protected `RealScanInputContractDTO` assembly must remain behind a separate authorization gate. That future gate may define how to assemble:

- symbol;
- Watchlist Pool proof;
- watchlist config version;
- requested scan reason;
- requested timeframes;
- scan timestamp;
- stale/missing behavior;
- risk blockers;
- review-only flags;
- guard validation result.

The assembly must fail closed when proof, proof source, timeframe, timestamp, data availability, or risk-blocker state is missing, stale, contradictory, or unauthorized.

Any future assembly must pass through `RealScanInputContractGuardValidator` and preserve `manualReviewRequired=true` and `notTradeInstruction=true`. A valid-looking input can remain review-only, but it cannot become a trade instruction.

## 5. Market-Read Java Still Blocked

Future market-read Java must not be implemented until a separate authorization gate has passed.

That future gate must specify:

- the exact data request contract;
- the allowed proof source for Watchlist Pool membership;
- stale/missing data behavior;
- fail-closed validation rules;
- targeted-test-only requirements;
- the no-output / no-score / no-Candidate / no-Push / no-Readiness / no-point / no-trading limits.

P285 does not authorize `MarketQuoteClient`, `BinanceMarketQuoteClient`, runtime/live/external reads, provider credentials, live provider calls, scan output, real scan loop, production score, Candidate production workflow, Push execution, scheduler/API/dashboard wiring, Readiness, point generation, order, execution, or auto-trading.

## 6. Safety Boundaries

- Risk Action Guard must remain before delivery / Push / Readiness.
- 踩踏状态禁止机会推送。
- 插针不等于趋势反转。
- 强反转不等于直接反手。
- Display Slots / 默认六币 cannot be scan universe or batch universe.
- Watchlist Pool remains the scan candidate boundary.
