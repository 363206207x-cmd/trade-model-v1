# BACKEND-P292 MarketReadRequest Test-Only Wiring and Review-Only Assembler Slice

P292 is a business-chain MAX_SAFE_PACK.

It advances the MarketReadRequest chain from DTO + GuardValidator skeleton to test-only wiring.

## Capability Movement

- Before: `MarketReadRequest test-only wiring = 0 NOT_STARTED`
- After: `MarketReadRequest test-only wiring = 4 TEST_ONLY_WIRING`

This is not a closure-only package. It proves the DTO -> GuardValidator chain can execute inside test scope and return review-only validation output.

## Completed Slice

P292 adds a test-only helper that:

- accepts a `MarketReadRequestDTO`;
- calls `MarketReadRequestGuardValidator`;
- returns `MarketReadRequestGuardValidationResult`;
- preserves `blockingReasons`;
- preserves `riskBlockers`;
- keeps blocked paths blocked;
- keeps valid review-only DTOs review-only and manual-review required.

## Review-Only Outputs

P292 allows only:

- validation status;
- blocking reasons;
- risk blockers;
- manual review required;
- fail-closed reason;
- not-trade-instruction flag.

P292 does not output entry zone, stop zone, TP / RR, order intent, execution intent, readiness upgrade, push message, or candidate promotion.

## Not Production Wiring

P292 is not production wiring.

It does not connect `MarketQuoteClient` or `BinanceMarketQuoteClient`.

It does not read runtime/live/external data.

It does not create scan output, score, Candidate, Push, Readiness, point generation, entry / stop / TP / RR, order behavior, execution behavior, or auto-trading.

## Why This Matters

P292 fixes the previous "only boundaries, no chain" problem by moving one business-chain node from static DTO/validator tests into test-only wiring.

The next step should be review-only MarketRead output / scan output, not another closure-only or repeated authorization gate.
