# P313 SourceTrace Numeric Point Contract Plan

## Purpose

P313 belongs to the Readiness / Point Mainline.

P313 is a docs-only SourceTrace contract plan after P312 `SOURCE_OWNED_NUMERIC_POINT_PROPOSAL_PLAN`.

It defines what future entry / stop / TP / RR numeric values must bind to before they may appear in a source-owned review-only numeric point proposal.

P313 does not create Java DTOs, does not implement numeric point proposal, does not generate real entry / stop / TP / RR, does not connect dashboard runtime, does not connect external channels, and does not connect order / execution / auto-trading.

## What P313 Is Not

P313 is docs-only.

P313 does not raise Production Runtime Progress.

P313 does not mean a SourceTrace Java DTO is complete.

P313 does not mean numeric point proposal is implemented.

P313 does not mean real entry / stop / TP / RR are complete.

P313 does not mean dashboard runtime integration.

P313 does not mean external push.

P313 does not mean order, execution, or auto-trading.

P313 does not allow direct order placement after merge.

## SourceTrace Contract Boundary

Every future numeric point value must be owned by a source trace. A value without a trace is not a value for display; it is an `INCOMPLETE` missing reason.

The contract answers four questions for every value:

- who owns this numeric source;
- which upstream contract produced it;
- when and from which market context it was observed;
- which Risk Action Guard result allowed it to remain review-only.

SourceTrace can support only review-only numeric proposal. It cannot support a buy, sell, long, short, open, close, reverse, order, execution, or auto-trading action.

## Minimum SourceTrace Fields

Every future numeric point source trace must include at least:

| Field | Required meaning |
|---|---|
| `sourceTraceId` | Stable trace id for this numeric source. Missing id means `INCOMPLETE`. |
| `sourceOwner` | Owning subsystem, such as `READINESS_POINT_MAINLINE`, `RISK_ACTION_GUARD`, or `RUNTIME_KLINE_CONTEXT`. |
| `sourceContractId` | Versioned source contract that produced the value. |
| `symbol` | Market symbol that exactly matches the proposal symbol. |
| `market` | Market or venue context used by the source. |
| `timeframe` | Timeframe that owns the observed value. |
| `sourceType` | Entry boundary, stop invalidation, TP target, RR formula, liquidity guard, or equivalent source type. |
| `sourceValue` | Nullable primary numeric value. If null, `missingReason` is required. |
| `sourceValueLow` | Nullable lower bound for a zone or range. |
| `sourceValueHigh` | Nullable upper bound for a zone or range. |
| `sourceUnit` | Unit such as price, percent, ratio, or label. |
| `observedAt` | Time the market condition was observed. |
| `createdAt` | Time this trace was created. |
| `freshnessStatus` | `FRESH`, `STALE`, `UNKNOWN`, `CONFLICTED`, or `FORGED_OR_UNTRUSTED`. |
| `staleReason` | Required when freshness is stale, unknown, or conflicted. |
| `dataQualityScore` | Data quality score used by the gate. Missing or below threshold blocks numeric display. |
| `runtimeKlineContextRef` | Reference to the runtime kline context used to observe the value. |
| `upstreamSnapshotRef` | Reference to upstream review-only snapshot or fixture context. |
| `watchlistPoolProof` | Proof that the symbol came from Watchlist Pool, not Display Slots. |
| `riskActionGuardRef` | Reference to the Risk Action Guard result that was evaluated before numeric proposal. |
| `sourceReason` | Review-only reason for the source. It must not contain execution language. |
| `sourceRef` | Stable source reference for lookup and fixture validation. |
| `derivedFromSourceRefs` | Source refs used to derive this source, if any. |
| `missingReason` | Required when a required value or reference is unavailable. |
| `blockedReason` | Required when the source is blocked fail-closed. |

## Source Owner And Source Contract

`sourceOwner` identifies the subsystem accountable for a numeric value. It is not a person and not free-form prose. It must be stable enough for tests, fixtures, and review.

`sourceContractId` identifies the versioned contract that produced the trace. It must be specific enough to distinguish entry boundary traces, stop invalidation traces, TP ladder traces, RR formula traces, RuntimeKlineContext traces, and Risk Action Guard traces.

If either `sourceOwner` or `sourceContractId` is missing, ambiguous, forged, or mismatched with the proposal symbol / timeframe, the future numeric proposal must not show a value.

## Time And Freshness

`observedAt` is when the market condition was observed.

`createdAt` is when the trace object was created.

`freshnessStatus` is evaluated against the decision window and the referenced runtime kline context:

- `FRESH`: source `observedAt`, `createdAt`, and `runtimeKlineContextRef` match the decision window.
- `STALE`: source exceeds the allowed window, or the upstream runtime kline context is stale.
- `UNKNOWN`: required timestamps or freshness context are missing.
- `CONFLICTED`: multiple sources claim the same numeric role but disagree.
- `FORGED_OR_UNTRUSTED`: the source cannot be traced or is suspected to be forged.

Freshness outcomes:

- `STALE` -> `INCOMPLETE`.
- `UNKNOWN` -> `INCOMPLETE`.
- `CONFLICTED` -> `INCOMPLETE` when it only prevents review, or `BLOCKED_FAIL_CLOSED` when it could induce a trade.
- `FORGED_OR_UNTRUSTED` -> `BLOCKED_FAIL_CLOSED`.

## Data Quality, Runtime Context, Risk Guard, And Watchlist Proof

`dataQualityScore` enters the source trace as a required gate input. Missing score or score below the configured threshold means `INCOMPLETE`; below a hard threshold means `BLOCKED_FAIL_CLOSED`.

`runtimeKlineContextRef` binds the trace to the market context used to observe the value. If missing, stale, mismatched, or derived only from latest price, the value must not display.

`riskActionGuardRef` binds the trace to Risk Action Guard. SourceTrace cannot bypass Risk Action Guard, and the guard ref must exist before numeric values are allowed into review-only proposal.

`watchlistPoolProof` binds the trace to Watchlist Pool. Display Slots are not a source of point proposal eligibility. Missing proof means `INCOMPLETE`.

## Entry SourceTrace Contract

Entry source trace must cover:

- entry boundary source;
- entry zone source;
- entry timeframe;
- entry observed window;
- entry source reason;
- entry invalidation reference;
- entry missing reason;
- why entry is review-only;
- why entry is not buy / long / open instruction.

Entry source trace must not come only from latest price, dashboard text, candidate label, score label, AI prose, or manual fill.

If entry source trace is missing or stale, a future proposal may show only `entryMissingReason`; it must not display a numeric entry value.

## Stop SourceTrace Contract

Stop source trace must cover:

- invalidation source;
- swing / structure / volatility buffer source;
- stop zone source;
- stop timeframe;
- stop observed window;
- stop source reason;
- stop missing reason;
- why stop is review-only;
- why stop is not an automatic stop-loss order;
- why stop is not a market close suggestion.

Stop source trace must not imply immediate close, forced stop, market liquidation, or automatic order placement.

## TP SourceTrace Contract

TP source trace must cover:

- TP level source;
- TP zone source;
- resistance / support / liquidity target / RR ladder source;
- TP timeframe;
- TP observed window;
- TP source reason;
- TP allocation review-only reason;
- TP missing reason;
- why TP is review-only;
- why TP is not an automatic take-profit order;
- why TP is not a sendable order.

TP ladder sources must remain nullable and may expose only review-only allocation context.

## RR SourceTrace Contract

RR source trace must cover:

- RR formula;
- entry source ref;
- stop source ref;
- TP source ref;
- calculation trace;
- source version;
- RR missing reason;
- why RR is review-only;
- why RR is not a standalone open-condition.

RR cannot be used alone as a permission to open a position.

## SourceTrace Missing, Stale, Forged, Or Ambiguous Handling

If source trace is missing, the future numeric point proposal must remain `INCOMPLETE` and expose a missing reason.

If source trace is stale, the future numeric point proposal must remain `INCOMPLETE` and expose a stale reason.

If source trace is ambiguous or mismatched, the future numeric point proposal must remain `INCOMPLETE` unless the ambiguity could induce a trade; then it must be `BLOCKED_FAIL_CLOSED`.

If source trace is forged or untrusted, the future numeric point proposal must be `BLOCKED_FAIL_CLOSED`.

If a trace can only support review-only missing reason, it must not support numeric display. This includes sources derived only from display text, score labels, candidate labels, latest price, AI prose, or human fill without contract-owned source refs.

## INCOMPLETE Conditions

Future numeric point proposal must stay `INCOMPLETE` when any condition is true:

- `sourceTraceId` missing;
- `sourceOwner` missing;
- `sourceContractId` missing;
- symbol / timeframe mismatch;
- `sourceValue` missing;
- `sourceValueLow` / `sourceValueHigh` incomplete;
- `observedAt` missing;
- `createdAt` missing;
- `freshnessStatus` is `UNKNOWN`;
- `freshnessStatus` is `STALE`;
- `dataQualityScore` missing;
- `dataQualityScore` below threshold;
- `runtimeKlineContextRef` missing;
- `upstreamSnapshotRef` missing;
- `watchlistPoolProof` missing;
- `riskActionGuardRef` missing;
- `missingReason` absent when value is null;
- source derived only from display text;
- source derived only from score / label / latest price.

`INCOMPLETE` may explain unavailable values, but it must not fabricate numeric values.

## BLOCKED_FAIL_CLOSED Conditions

Future numeric point proposal must become `BLOCKED_FAIL_CLOSED` when any condition is true:

- forged / untrusted source trace;
- source trace attempts to bypass Risk Action Guard;
- source trace implies buy / sell / long / short;
- source trace implies order intent;
- source trace implies execution intent;
- source trace implies auto-trading;
- source trace attempts external channel without authorization;
- source conflict would induce immediate reverse;
- stampede confirmed;
- liquidity severely degraded;
- data quality hard threshold failed.

`BLOCKED_FAIL_CLOSED` must never be softened into an executable display or hidden order intent.

## Risk Action Guard Integration

SourceTrace cannot bypass Risk Action Guard.

Risk Action Guard ref must enter source trace before any future numeric point value can be displayed.

High risk does not mean immediate stop.

High risk does not mean immediate reverse.

High risk does not mean immediate open.

Strong reversal does not mean direct reverse.

Wick / pin-bar behavior does not mean trend reversal.

Stampede state blocks opportunity push.

Degraded liquidity does not recommend one-shot market cutting.

Even a complete source trace cannot become a trading action.

## Allowed Review-Only Output

P313 allows only planning-language output:

- SourceTrace contract status;
- missing source reason;
- stale source reason;
- conflicted source reason;
- Risk Action Guard required reason;
- fixture matrix expectations;
- validator / contract PR prerequisites.

It does not allow numeric value generation.

## Final Conclusion

P313 moves the planning state from `SOURCE_OWNED_NUMERIC_POINT_PROPOSAL_PLAN` to `SOURCETRACE_NUMERIC_POINT_CONTRACT_PLAN`.

It defines the minimum trace contract that future numeric point values must satisfy. It keeps all point work review-only, incomplete-safe, fail-closed, and blocked from executable trading semantics.
