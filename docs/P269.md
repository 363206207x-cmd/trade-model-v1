## 4. Future Message Envelope Scope

A future message envelope may only be introduced after separate authorization.

The first allowed shape must be a disabled no-op Java skeleton.

That future skeleton must start:

- disabled-by-default
- fail-closed
- audit-only
- review-only
- no-message-sending
- no-provider

The future message envelope may only represent an internal, non-sendable review object. It must not render final send text, send a message, pick a provider, call any external channel, activate scheduler behavior, connect API / dashboard, read runtime / live / external data, upgrade Readiness, generate point levels, or create trading actions.
