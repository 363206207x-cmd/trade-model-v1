# P321 Numeric Point Safety Validator Java Skeleton

## Purpose

P321 belongs to the Readiness / Point Mainline.

P321 follows P320 `REVIEW_ONLY_NUMERIC_POINT_PROPOSAL_DTO_JAVA_SKELETON`.

P321 adds a minimal plain Java `NumericPointSafetyValidator` skeleton and targeted tests for `ReviewOnlyNumericPointProposalDTO`.

P321 checks whether the DTO remains review-only, incomplete-safe, fail-closed when blocked, and not a trade instruction.

P321 is not a point generator, not an assembler, not a service, not dashboard runtime integration, not external push, and not order / execution / auto-trading.

## What P321 Adds

P321 adds:

- `src/main/java/org/example/trademodel/validator/point/NumericPointSafetyValidator.java`;
- `src/test/java/org/example/trademodel/validator/point/NumericPointSafetyValidatorTest.java`.

The validator accepts `ReviewOnlyNumericPointProposalDTO` and returns a nested `ValidationResult`.

The validation result supports:

- `INCOMPLETE`;
- `BLOCKED_FAIL_CLOSED`;
- `REVIEW_ONLY_NUMERIC_POINT_CANDIDATE`;
- `REVIEW_ONLY_NUMERIC_POINT_DEGRADED`.

These statuses are review-only validation statuses only. They are not trading instructions.

## Safety Checks

The validator requires these DTO flags to remain true:

- `reviewOnly`;
- `notTradeInstruction`;
- `manualReviewRequired`;
- `recheckRequired`;
- `riskActionGuardRequired`;
- `sourceTraceRequired`;
- `runtimeKlineContextRequired`;
- `dataQualityRequired`;
- `multiTimeframeRequired`;
- `incompleteSafe`.

If any safety flag is false, the result is `BLOCKED_FAIL_CLOSED`.

If DTO status is `BLOCKED_FAIL_CLOSED`, the validator requires:

- `failClosed = true`;
- non-empty blocked reasons.

## Contract Ref Checks

For `REVIEW_ONLY_NUMERIC_POINT_CANDIDATE`, the validator requires:

- source trace refs;
- runtime kline context refs;
- data quality context ref;
- multi-timeframe context ref;
- Risk Action Guard ref;
- Watchlist Pool proof.

For `REVIEW_ONLY_NUMERIC_POINT_DEGRADED`, refs are still checked, and missing / degraded reasons must be present.

For `INCOMPLETE`, refs may be missing, but missing reasons must be present.

For `BLOCKED_FAIL_CLOSED`, blocked reasons must be present.

## Point Field Checks

The validator does not calculate point fields.

It checks only presence and missing-reason semantics:

- candidate status requires entry, stop, TP levels, and RR field;
- degraded status may omit partial point fields if missing reasons explain the gap;
- incomplete status may omit all point fields if missing reasons are present;
- blocked status must remain fail-closed and cannot be treated as a usable point.

## Forbidden Semantics

The validator rejects executable trading language in public status, reasons, or forbidden-semantics input.

When executable semantics are detected, the result is `BLOCKED_FAIL_CLOSED`.

The normal safe outputs do not contain buy / sell / long / short / order / execute / auto-trade semantics.

## Validation Scope

The targeted test verifies:

- null proposal returns `INCOMPLETE`;
- incomplete / blocked / candidate / degraded status handling;
- required refs for candidate;
- required point fields for candidate;
- degraded missing reason handling;
- forbidden executable semantics fail closed;
- safety flags must remain true;
- validator output remains free of executable semantics in normal safe results;
- validator has no Spring annotations, provider clients, service/controller/mapper/repository/scheduler refs, external channel refs, or order / execution / auto-trading refs.
