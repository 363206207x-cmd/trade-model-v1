# P343 Source-Owned Candidate Integration Boundary Plan

## Package Type

P343 is an A-risk docs-only boundary plan in the Readiness / Point Mainline.

It defines the future boundary for Source-Owned Candidate Integration after the source binding skeleton chain is closed through P342.

P343 is L0 only:

- L0 Boundary Plan: complete in this package;
- L1 DTO: not started in this package;
- L2 Validator: not started in this package;
- L3 Assembler: not started in this package;
- L4 Verification: not started in this package;
- L5 Internal wiring: not started;
- L6 Dashboard preview: not started;
- L7 Runtime-safe usable: not started.

P343 does not raise Production Runtime Progress.

## Capability Movement

`WATCHLIST_POOL_PROOF_SOURCE_BINDING_ABILITY_CLOSURE -> SOURCE_OWNED_CANDIDATE_INTEGRATION_BOUNDARY_PLAN`

This movement defines only the boundary before any future source-owned candidate integration source binding or assembler work.

It does not implement integration.

## Positioning

Source-Owned Candidate Integration sits after source binding and before review-only numeric point candidate assembly.

The intended future chain is:

`SourceTrace + RuntimeKlineContext + DataQualityContext + MultiTimeframeContext + RiskActionGuard + WatchlistPoolProof -> Source-Owned Candidate Integration -> SourceOwnedNumericPointCandidateAssembler -> ReviewOnlyNumericPointProposalAssembler -> NumericPointSafetyValidator`

Source-Owned Candidate Integration is:

- a candidate integration boundary;
- a review-only readiness summarizer for source binding completeness;
- an incomplete-safe / fail-closed handoff point.

It is not:

- a trading execution layer;
- a push sending layer;
- a final direction decision layer;
- an automatic order layer;
- a real point generation layer;
- a runtime market data reader.

## Required Upstream Source Bindings

Future candidate integration may be considered only when all required upstream source bindings can provide review-only, incomplete-safe, fail-closed contexts:

- SourceTrace;
- RuntimeKlineContext;
- DataQualityContext;
- MultiTimeframeContext;
- RiskActionGuard;
- WatchlistPoolProof.

Each upstream context must preserve:

- `reviewOnly=true`;
- `notTradeInstruction=true`;
- `manualReviewRequired=true`;
- `incompleteSafe=true`;
- trusted source proof;
- source refs and context refs;
- explicit missing / degraded / blocked reasons where applicable.

Missing source binding context is not silently tolerated.

## Required Input Boundary

Future source-owned candidate integration may read only explicit source-owned binding results from the source binding skeleton families.

Allowed future inputs are:

- SourceTrace source refs and validation status;
- RuntimeKlineContext binding status and refs;
- DataQualityContext binding status and score/threshold result;
- MultiTimeframeContext binding status and conflict/alignment result;
- RiskActionGuard binding status and blocked/degraded result;
- WatchlistPoolProof binding status and membership proof;
- source binding completeness summary;
- explicit unavailable / degraded / blocked reasons.

It must not read:

- market data provider output;
- latest price;
- latest close;
- dashboard text;
- AI prose;
- score labels without source-owned proof;
- display slots as proof;
- watchlist service runtime;
- order / position / account execution path;
- external channel state.

## Incomplete-Safe Conditions

Future Source-Owned Candidate Integration must return only `INCOMPLETE` when any required evidence is missing, stale, conflicted, or not review-ready.

At minimum, `INCOMPLETE` is required when:

- SourceTrace refs are missing;
- RuntimeKlineContext is missing;
- RuntimeKlineContext is stale;
- DataQualityContext is missing;
- DataQualityContext does not pass incomplete-safe thresholds;
- MultiTimeframeContext is missing;
- MultiTimeframeContext is unconfirmed;
- MultiTimeframeContext conflict is unresolved or too high for review-only candidate consideration;
- RiskActionGuard context is missing;
- WatchlistPoolProof is missing;
- WatchlistPoolProof is stale;
- source binding completeness summary is missing;
- any upstream context lacks explicit missing / degraded reason when it cannot produce review-ready output;
- only latest price exists;
- only latest close exists;
- only display slot state exists;
- only dashboard text exists;
- only AI prose exists.

`INCOMPLETE` must remain review-only and manual-review required.

## Fail-Closed Conditions

Future Source-Owned Candidate Integration must return only `BLOCKED_FAIL_CLOSED` when any upstream context indicates unsafe or executable behavior.

At minimum, `BLOCKED_FAIL_CLOSED` is required when:

- any upstream source binding is not trusted;
- any upstream binding has `reviewOnly=false`;
- any upstream binding has `notTradeInstruction=false`;
- any upstream binding has `manualReviewRequired=false`;
- any upstream binding attempts to bypass its validator;
- any upstream context contains executable semantics;
- SourceTrace source is forged / untrusted;
- RuntimeKlineContext has blocked severe gap / stampede / forged evidence state;
- DataQualityContext hard threshold fails;
- MultiTimeframeContext has high trade-inducing conflict;
- RiskActionGuard is blocked;
- RiskActionGuard confirms stampede;
- RiskActionGuard sees wick-only reverse semantics;
- RiskActionGuard sees liquidity-degraded one-shot exit semantics;
- WatchlistPoolProof is disabled;
- WatchlistPoolProof is empty;
- WatchlistPoolProof indicates non-member asset;
- WatchlistPoolProof is untrusted;
- Display Slot or default home asset is used as Watchlist Pool proof;
- external channel is attempted;
- Push send is attempted;
- order intent is attempted;
- execution intent is attempted;
- auto-trading action is attempted.

Fail-closed output must not produce a usable candidate.

## Watchlist Pool Boundary

Watchlist Pool is the maximum boundary for candidate / opportunity-push eligibility.

The boundary is fixed:

- Display Slots are not Watchlist Pool proof;
- default six home assets are not Watchlist Pool proof;
- default display does not authorize push candidacy;
- an asset outside Watchlist Pool cannot enter candidate integration;
- stale or untrusted membership proof cannot pass;
- disabled / empty Watchlist Pool blocks candidate integration.

P343 does not connect Watchlist runtime, Watchlist service, rule config, audit tables, dashboard runtime, or Push send.

## Risk Action Guard Boundary

Risk Action Guard remains mandatory before future candidate integration may become review-ready.

The boundary is fixed:

- high risk does not mean immediate stop;
- high risk does not mean immediate reverse;
- high risk does not mean immediate open;
- strong reversal does not mean direct reverse;
- wick-only does not mean trend reversal;
- stampede state blocks opportunity push, reverse, and new open semantics;
- liquidity degradation must not become one-shot market cut semantics;
- any executable action semantics must fail closed.

Risk Action Guard is an action-review boundary, not an execution engine.

## Candidate Output Boundary

P343 defines only future review-only fields that may be considered for candidate integration output. It does not implement them.

Future source-owned candidate integration may output at most:

- candidate integration readiness status;
- candidate unavailable reason;
- source binding completeness summary;
- review-only candidate boundary label;
- review-only candidate blocked reason;
- review-only candidate degraded reason;
- source-owned candidate integration trace refs;
- `notTradeInstruction=true`;
- `manualReviewRequired=true`.

Future source-owned candidate integration must not directly output:

- executable entry;
- executable stop;
- executable TP;
- executable RR;
- final direction;
- order intent;
- execution intent;
- auto-trading action;
- push send payload;
- external channel message.
