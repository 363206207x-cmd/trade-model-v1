## 持仓监控完整方案

### 一、模块定位

持仓监控不是一个孤立页面，也不是自动交易模块。

它在 V1 里的定位是：

执行建议之后、复盘之前的持续验证环节。

V1 的主链路是：

原始数据接入 → 原始证据生成 → 证据标准化 → 八大评分 → 综合决策 → 执行计划 → 持仓监控 → 结果复盘 → 规则修正与版本迭代

所以持仓监控的核心目标不是“帮用户自动交易”，而是：

用户真实开仓后，系统持续判断：
这笔仓位的原始入场逻辑还在不在、行情有没有反转、风险有没有升级、执行计划是否需要调整，并把全过程留档进入复盘。

## 二、核心原则

### 1. 系统建议 ≠ 用户真实开仓

系统可以生成：

当前方向判断

是否值得开仓

推荐入场区

推荐止损区

推荐止盈方案

杠杆上限

最大仓位

计划失效条件

执行计划建议

但这些只属于：

执行建议 / 候选计划

不能直接等同于：

已开仓 / 当前持仓 / 正在监控仓位

### 2. 达到入场条件 ≠ 已经开仓

即使系统判断：

当前已触发入场条件

也不能自动把页面状态改成：

已开仓

正确逻辑是：

只有用户手动录入真实开仓信息后，系统才进入已开仓监控。

### 3. 手动录入后才启动持仓监控

用户至少需要手动录入：

币种

持仓方向：做多 / 做空

开仓价

开仓时间

建议同时支持录入：

仓位大小

杠杆倍数

仓位占账户比例

用户实际止损价

用户实际止盈价

关联的系统执行计划

用户备注

录入后，系统才把这笔仓位作为一个可追踪对象，进入持仓监控。

### 4. 平仓后首页监控清空

用户记录平仓后：

首页不再显示该仓位为“监控中”

持仓区域显示“暂无持仓”或空白

已结束记录进入复盘页

复盘页保留完整过程

这符合之前敲定的口径：

平仓后首页显示空白即可。

## 三、持仓监控的业务闭环

完整闭环如下：

系统生成执行建议
→ 用户人工判断并实际开仓
→ 用户手动录入开仓信息
→ 系统启动持仓监控
→ 定期 / 事件触发重新分析
→ 判断入场逻辑是否仍成立
→ 判断行情是否反转
→ 判断风险是否升级
→ 输出持有 / 减仓 / 收紧止损 / 退出观察等结构化建议
→ 用户手动记录平仓
→ 进入复盘
→ 复盘结果反馈到规则修正与版本迭代

一句话：

持仓监控就是把“进场后的持续验证”系统化，避免开仓后完全靠主观情绪处理。

## 五、入场逻辑是否仍成立

这是持仓监控的第一核心。

用户开仓后，系统不能只看盈亏，而要反复检查：

当初支持开仓的理由，现在还在不在？

### 1. 检查内容

系统需要重新分析：

原始入场方向是否仍被支持

当初的关键证据是否仍有效

八大评分是否明显变弱

多周期是否仍然收敛

结构位是否仍然有效

资金推动是否还在

杠杆风险是否升高

流动性质量是否恶化

情绪温度是否过热

事件冲击是否发生变化

AI 三方裁决是否出现冲突

### 2. 判断结果

可以分成三类：

#### 1）入场逻辑仍成立

说明：

原方向仍被支持

证据链没有明显破坏

风险没有明显升级

系统输出：

继续持有，维持当前监控。

#### 2）入场逻辑弱化

说明：

原方向仍未完全失效

但支持证据变弱

出现部分反向证据

置信度下降

系统输出：

原入场逻辑正在弱化，建议降低预期，不建议加仓，可考虑收紧止损或减仓观察。

#### 3）入场逻辑失效

说明：

关键结构被破坏

多周期明显不再支持

AI 裁决与持仓方向冲突

风险评分明显恶化

原执行计划的成立条件已经不存在

系统输出：

原执行计划已失效，请人工确认是否平仓、减仓或重新制定计划。

注意：

系统不能自动假设用户已经平仓。
即使计划失效，也只能提示用户处理，不能自动把持仓改成已结束。

## 六、行情是否反转

这是持仓监控的第二核心。

行情反转不是简单看价格涨跌，而是看：

原方向是否被新的证据链推翻。

### 1. 反转判断维度

#### 1）价格结构

做多时重点看：

是否跌破关键支撑

是否跌破入场逻辑依赖的结构位

是否突破失败后放量回落

是否反抽失败

做空时重点看：

是否突破关键压力

是否突破原本压制位

是否回踩不破

是否空头结构被破坏

#### 2）多周期收敛

重点看：

4h 方向是否改变

1h 结构是否转弱

15m 是否提前反向

5m 是否出现插针或短线反杀

如果用户做多，但变成：

4h 震荡

1h 转弱

15m 偏空

5m 插针风险升高

则说明：

多周期正在失去对原持仓方向的支持。

#### 3）八大评分变化

重点看：

趋势结构分是否下降

资金推动分是否减弱

杠杆风险分是否恶化

流动性质量分是否下降

情绪温度是否过热

事件冲击分是否升高

宏观环境分是否反向

综合可信度分是否下降

#### 4）资金与链上变化

重点看：

OI 是否异常上升或快速下降

Funding 是否极端

爆仓数据是否异常

大额转账是否冲击市场

ETF 资金流是否明显反向

量价是否背离

#### 5）AI 三方裁决

重点看：

GPT 最终裁决是否仍支持原方向

Gemini 是否指出原逻辑漏洞

Grok 是否发现突发新闻或情绪反转

三方是否冲突扩大

## 七、持仓监控的触发机制

持仓监控不应该只靠用户手动刷新，应该支持两类触发。

### 1. 定时触发

根据 V1 周期设计：

5m：用于插针、短线异常、流动性风险

15m：用于短线结构变化

1h：用于中周期方向验证

4h：用于大方向确认

建议页面展示时可以简化为：

系统定期重新验证持仓逻辑。

不用在 UI 上暴露过多技术细节。

### 2. 事件触发

出现以下情况时，应立即触发重新分析：

价格接近止损

价格接近止盈

关键结构位被突破或跌破

成交量突然放大

OI / Funding 异常

爆仓数据异常

5m 插针风险升高

重大新闻出现

宏观事件临近

ETF 资金流明显异常

AI 三方裁决出现重大冲突

数据质量评分明显下降

## 八、监控输出结果

持仓监控每次运行后，不应该只输出一句“继续持有”或“风险升高”。

应该输出结构化结果。

### 1. 当前持仓状态

例如：

监控中

逻辑仍成立

逻辑弱化

计划失效

接近止损

接近止盈

高风险观察

等待用户确认平仓

已平仓

### 2. 当前方向判断

例如：

仍支持做多

仍支持做空

转为震荡

短线反向

高周期未变，低周期转弱

多周期冲突扩大

### 3. 当前风险等级

例如：

低

中

高

极高

### 4. 系统建议动作

建议动作要克制，不能越界成自动交易。

可以包括：

继续持有

暂不加仓

降低仓位

收紧止损

移动止损

到达止盈区后分批止盈

计划失效，等待人工确认

记录平仓并进入复盘

不建议当前阶段加入：

自动平仓

自动反手

自动加仓

自动下单

## 九、风险监控维度

持仓监控至少覆盖以下维度。

### 1. 止损 / 止盈监控

系统需要持续判断：

当前价距离用户止损还有多远

当前价距离用户止盈还有多远

是否触及系统建议止损区

是否触及系统建议止盈区

用户实际止损是否偏离系统建议

是否需要移动止损

### 2. 浮盈浮亏监控

显示：

当前浮盈浮亏

盈亏百分比

盈亏对应账户影响

杠杆下的实际风险暴露

### 3. 仓位风险监控

重点看：

当前仓位是否过大

杠杆是否过高

单笔风险是否超过规则阈值

多个持仓之间是否高度相关

同向仓位是否过于集中

### 4. 持仓时间监控

如果一笔仓位超过原计划持有周期，应提醒：

持仓时间已超过原执行计划预期，请重新确认是否继续持有。

这可以避免：

短线计划被用户拖成中长线被动持仓。

### 5. 外部冲击监控

包括：

重大新闻

宏观事件

ETF 资金流

监管消息

黑天鹅事件

市场情绪急剧变化

### 6. 异常行情监控

包括：

5m 插针

成交量突变

流动性变差

爆仓异常

快速拉升后回落

快速下跌后反抽失败

大额链上转移

鲸鱼异动

推荐止盈区

### 2. 用户持仓记录

建议新增或明确一个“用户实际持仓记录”对象。

它记录：

用户真实开仓价

用户真实方向

## 十四、页面状态机

建议持仓监控页面采用以下状态。

### 状态 1：暂无持仓

显示：

当前暂无手动录入持仓。

可以显示系统最新执行建议，但不能显示为持仓。

### 状态 2：有执行建议，未开仓

显示：

系统存在执行建议，但尚未录入真实持仓。

可操作：

查看执行计划

手动录入已开仓

### 状态 3：已开仓，监控中

显示：

已录入真实持仓，系统正在持续监控。

展示：

开仓信息

当前价

浮盈浮亏

逻辑是否成立

是否反转

风险等级

当前建议动作

### 状态 4：逻辑弱化 / 风险升高

显示：

原入场逻辑正在弱化，风险升高，请关注是否调整计划。

可操作：

继续持有

调整止损

减仓记录

记录平仓

### 状态 5：计划失效，等待人工确认

显示：

原执行计划已失效，但系统无法确认你是否已经平仓，请手动处理。

可操作：

继续持有并备注原因

已减仓

已平仓

重新制定计划

### 状态 6：已平仓，进入复盘

显示：

本次持仓已结束，监控停止，记录已进入复盘。

首页该持仓监控清空。

## 十五、当前阶段不做什么

为了避免项目走偏，当前阶段不要做这些：

不做自动开仓。

不做自动平仓。

不做自动反手。

不做交易所真实下单。

不把“系统执行建议”直接当成“用户真实持仓”。

不因为达到入场条件就自动显示已开仓。

不把首页做成过度复杂的交易终端。

不在没有复盘字段确认前乱加大量 UI 字段。

不把用户实际止损/止盈和系统建议止损/止盈混在一起。

不让推送变成噪音提醒系统。

## 十六、最终版一句话定义

V1 持仓监控模块，是在用户手动录入真实持仓后，基于系统原执行计划、原始证据链、八大评分、多周期收敛、AI 三方裁决、行情结构、资金与事件风险，对该持仓进行定期和事件触发的持续验证；系统判断入场逻辑是否仍成立、行情是否反转、风险是否升级，并输出结构化调整建议，最终将完整过程沉淀到复盘页，用于判断系统规则问题、用户执行偏差和后续规则版本迭代。
