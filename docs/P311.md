# P311 Executable Point Generation Pre-Approval Plan

## Purpose

P311 belongs to the Readiness / Point Mainline.

It is a docs-only pre-approval plan after P310 `REVIEW_ONLY_POINT_PROPOSAL_CLOSURE_DISPLAY_GATE`.

P311 defines when the project may later consider moving from a review-only placeholder to a source-owned numeric point proposal. It does not implement that move.

## Current Completed Upstream Chain

The upstream chain is complete only to internal review-only display:

`ReviewOnlyPointBoundaryGateDTO`
-> `ReviewOnlyPointProposalDTO`
-> `ReviewOnlyPointProposalDisplayDTO`

P310 proved that point proposal output can become a safe internal display object while preserving review-only, incomplete-safe, not-trade-instruction, manual-review, recheck, Risk Action Guard, source-trace, and runtime-kline-context requirements.

## What P311 Is Not

P311 is not executable point generation.

P311 is not a Java package.

P311 is not a dashboard package.

P311 is not dashboard runtime integration.

P311 is not external push authorization.

P311 is not order, execution, or auto-trading.

P311 does not make entry, stop, TP, or RR complete.

P311 does not raise Production Runtime Progress.

P311 does not permit direct order placement after merge.

## Required Future Chain

Future numeric point proposal work must use a separately approved chain:

`ReviewOnlyPointProposalDisplayDTO`
-> Executable Point Generation Pre-Approval
-> SourceTrace completeness gate
-> RuntimeKlineContext completeness gate
-> DataQuality gate
-> Multi-timeframe confirmation gate
-> Liquidity / Stampede / Wick / StrongReversal Risk Action Guard
-> Review-only Numeric Point Proposal
-> Manual Review
-> still no direct order / execution / auto-trading

P311 only defines this chain. It does not implement it.

## Approval Conditions For Numeric Point Proposal

A later package may only move from review-only placeholder to source-owned numeric point proposal when all of the following are true:

- source trace exists and is owned by the point source, not inferred from display text;
- runtime kline context exists for the symbol and decision window;
- data quality is at least 70 and above any future hard threshold;
- requested timeframes are present and sufficient for the proposal type;
- multi-timeframe confirmation is available and not directionally conflicting;
- liquidity state is known and not severely degraded;
- stampede state is known and not confirmed;
- wick / pin-bar behavior has confirmation and is not treated as trend reversal by itself;
- strong reversal evidence has multi-timeframe confirmation and does not imply direct reverse;
- Risk Action Guard has executed and passed;
- watchlistPoolProof is present;
- manual review remains required;
- the output remains `reviewOnly = true`, `notTradeInstruction = true`, and `manualReviewRequired = true`.

## Required Data Sources

Entry, stop, TP, and RR must come from source-owned traces:

| Point field | Required source |
|---|---|
| entry | traceable structure / boundary / support-resistance / pullback source with symbol, timeframe, observed window, freshness, and source reason |
| stop | traceable invalidation / swing / structural boundary source with source reason and timeframe |
| TP | traceable take-profit plan source such as resistance / support / liquidity target / RR ladder, not a fabricated target |
| RR | traceable calculation from entry, stop, and TP sources, with all inputs source-owned |

Latest price, dashboard display text, candidate labels, or a positive-looking score cannot be used as the sole source for point values.

## Required Source Trace

The following source trace must exist before future numeric proposal work:

- source owner and source contract id;
- symbol and timeframe;
- source type;
- source value or value range;
- observed time and decision-create time;
- freshness / staleness status;
- source reason;
- source reference;
- entry source trace;
- stop source trace;
- TP source trace;
- RR input source trace;
- multi-timeframe source trace;
- liquidity / stampede state source trace;
- Risk Action Guard result trace.

Missing, forged, ambiguous, stale, or mismatched trace keeps the proposal `INCOMPLETE` or `BLOCKED_FAIL_CLOSED`.

## Required Runtime Kline Context

Runtime kline context must include:

- OHLCV window for each required timeframe;
- latest price and timestamp;
- kline window start / end;
- data freshness and stale status;
- data quality score;
- gap / missing candle status;
- wick / pin-bar evidence and confirmation state;
- liquidity state;
- stampede state;
- event-risk / abnormal-data context when available.

Missing runtime context cannot be filled by a review-only placeholder.

## Data Quality Gate

Future numeric point proposal work must require:

- data quality >= 70 for review-only numeric proposal consideration;
- no hard-threshold failure;
- no missing OHLCV window;
- no stale source marked fresh;
- no unknown liquidity state treated as normal;
- no unknown stampede state treated as safe;
- no missing source trace treated as source-owned.

If the data quality score is below 70, the output must stay `INCOMPLETE`. If a future hard threshold fails, the output must become `BLOCKED_FAIL_CLOSED`.

## Multi-Timeframe Confirmation Gate

Future numeric point proposal work must require:

- minimum timeframe coverage for the proposal type;
- no unresolved higher-timeframe conflict;
- no lower-timeframe noise treated as structure;
- wick / pin-bar confirmation before any structural inference;
- strong reversal confirmation across multiple timeframes before any downgrade or reversal-adjacent review-only output.

Multi-timeframe agreement alone does not prove point readiness. It only removes one incomplete reason.

## Risk Action Guard Integration

Risk Action Guard is mandatory before any numeric point proposal.

The following rules are hard boundaries:

- high risk does not mean immediate stop;
- high risk does not mean immediate reverse;
- high risk does not mean immediate open;
- strong reversal does not mean direct reverse;
- wick / pin-bar behavior does not mean trend reversal;
- stampede state blocks opportunity push;
- degraded liquidity should not produce a one-shot market-cut suggestion;
- short-term wick behavior may only trigger risk reminder and wait-for-confirmation output;
- point generation must happen after Risk Action Guard, not before it;
- even if points are later generated, they must remain `reviewOnly = true`, `notTradeInstruction = true`, and `manualReviewRequired = true`.

## INCOMPLETE Rules

The output must remain `INCOMPLETE` when any of the following is true:

- source trace is missing;
- runtime kline context is missing;
- data quality is below 70;
- timeframe coverage is insufficient;
- multi-timeframe direction conflicts are unresolved;
- wick / pin-bar behavior is not confirmed;
- liquidity state is unknown;
- stampede state is unknown;
- Risk Action Guard has not executed;
- entry source is not traceable;
- stop source is not traceable;
- TP source is not traceable;
- RR source is not traceable;
- watchlistPoolProof is missing;
- manual review is not complete.

`INCOMPLETE` means the project may show missing-reason context. It does not mean the system may invent values.

## BLOCKED_FAIL_CLOSED Rules

The output must become `BLOCKED_FAIL_CLOSED` when any of the following is true:

- stampede is confirmed;
- liquidity is severely degraded;
- strong reversal is present without multi-timeframe confirmation;
- proposed point would imply an immediate reverse order;
- proposed point would imply an executable trade instruction;
- external channel is attempted before authorization;
- order or execution is attempted;
- auto-trading is attempted;
- source trace is forged or missing but point generation is attempted;
- data quality is below a future hard threshold;
- Risk Action Guard fails.

`BLOCKED_FAIL_CLOSED` means do not downgrade into hidden executable behavior.

## Review-Only Even If Point Values Exist

Even if a later package creates source-owned numeric proposal fields, those values can only be review-only when:

- manual review remains required;
- not-trade-instruction remains true;
- risk action guard remains visible;
- source traces remain visible;
- source-owned runtime context remains visible;
- there is no order intent;
- there is no execution intent;
- there is no external send.

Point values must not be rendered as buy, sell, long, short, open, close, reverse, order, execute, or auto-trade instructions.

## Prohibited Reverse / Open Suggestions

Future packages must prohibit reverse, open-short, or open-long suggestions when:

- the signal is only a strong reversal label without multi-timeframe confirmation;
- wick / pin-bar evidence is unconfirmed;
- liquidity is degraded or unknown;
- stampede is unknown or confirmed;
- source trace is missing, forged, stale, or ambiguous;
- Risk Action Guard fails or has not executed;
- the output would imply immediate executable action.

## External Channel And Execution Boundaries

External push must remain prohibited when:

- external channel C-level authorization is absent;
- the output is incomplete or fail-closed;
- Risk Action Guard failed or did not run;
- the output could be interpreted as a trade instruction.

Order, execution, and auto-trading must remain prohibited in all P311 outcomes.

## Required Independent PRs Before Java Implementation

Before any Java implementation for numeric point generation, the project needs separate PRs for:

1. Source-owned Numeric Point Proposal Plan or Point Generation Safety Gate Plan.
2. SourceTrace completeness contract and fixture matrix.
3. RuntimeKlineContext completeness contract and fixture matrix.
4. DataQuality and hard-threshold contract.
5. Multi-timeframe confirmation contract.
6. Liquidity / stampede / wick / strong reversal Risk Action Guard contract.
7. Review-only numeric point proposal skeleton.
8. Dashboard display safety review, if display changes are needed.

None of these may authorize order, execution, auto-trading, or external channel by default.

## Next Recommended Packs

After P311, the next safe package should be one of:

1. Source-owned Numeric Point Proposal Plan.
2. Point Generation Safety Gate Plan.

The next package should not be real executable point generation, external channel, order, execution, or auto-trading.

## Final Conclusion

P311 is a docs-only pre-approval plan.

It defines the conditions for a future source-owned numeric point proposal, keeps Risk Action Guard mandatory, and preserves incomplete-safe / fail-closed semantics.

It does not generate executable points, real entry / stop / TP / RR, external push, order, execution, or auto-trading.
