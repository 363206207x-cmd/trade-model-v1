# P318 Numeric Point Safety Validator Plan

## Purpose

P318 belongs to the Readiness / Point Mainline.

P318 is a docs-only Numeric Point Safety Validator plan after P317 `RISK_ACTION_GUARD_NUMERIC_POINT_CONTRACT_PLAN`.

It defines how a future unified validator must check SourceTrace, RuntimeKlineContext, DataQuality, MultiTimeframe, Risk Action Guard, Watchlist Pool proof, safety flags, forbidden semantics, and partial entry / stop / TP / RR availability before any review-only numeric point candidate can be displayed or reviewed.

P318 does not create Java validator classes, does not create DTOs, does not implement numeric point proposal, does not generate real entry / stop / TP / RR, does not connect dashboard runtime, does not connect external channels, and does not connect order / execution / auto-trading.

## What P318 Is Not

P318 is docs-only.

P318 does not raise Production Runtime Progress.

P318 does not mean Safety Validator Java is complete.

P318 does not mean numeric point proposal is implemented.

P318 does not mean real entry / stop / TP / RR are complete.

P318 does not mean dashboard runtime integration.

P318 does not mean external push.

P318 does not mean order, execution, or auto-trading.

P318 does not allow direct order placement after merge.

## Validator Responsibility Boundary

The future Numeric Point Safety Validator is the final review-only safety check before a numeric point draft may become a `REVIEW_ONLY_NUMERIC_POINT_CANDIDATE`.

It is responsible for:

- checking that all required upstream contract contexts exist;
- preserving source ownership and traceability;
- preserving runtime kline context and freshness;
- enforcing data-quality thresholds;
- enforcing multi-timeframe confirmation;
- enforcing Risk Action Guard results;
- keeping Watchlist Pool proof as the candidate boundary;
- rejecting forbidden trade / order / execution / external-send semantics;
- producing `INCOMPLETE`, `BLOCKED_FAIL_CLOSED`, degraded review-only, or review-only candidate states.

It is not responsible for generating prices, calculating trade direction, producing executable points, sending messages, placing orders, or executing trades.

## Planned Validator Inputs

The future validator should receive at least:

| Input | Meaning |
|---|---|
| `ReviewOnlyNumericPointProposal` draft / candidate | Future review-only numeric point draft, never executable. |
| `SourceTrace` context | Source-owned trace for entry / stop / TP / RR values and missing reasons. |
| `RuntimeKlineContext` context | Runtime kline window and market context. |
| `DataQuality` context | Data quality score, thresholds, and degradation / blocked reasons. |
| `MultiTimeframe` context | Timeframe alignment, conflict, wick / noise, and strong-reversal context. |
| `RiskActionGuard` context | Hard risk gate output. |
| `WatchlistPoolProof` | Proof that the candidate belongs to Watchlist Pool, not Display Slots. |
| `requestedTimeframes` | Requested review timeframes. |
| `symbol` | Symbol under validation. |
| `market` | Market or venue. |
| `evaluationTimestamp` | Validator evaluation timestamp. |

P318 only defines this plan. It does not create Java classes.

## Planned Validator Output States

The future validator output states must include at least:

| Status | Meaning |
|---|---|
| `INCOMPLETE` | Required source, context, quality, timeframe, guard, proof, or missing reason is unavailable. |
| `BLOCKED_FAIL_CLOSED` | Unsafe, forged, executable, external-send, order, execution, or bypass behavior is detected. |
| `REVIEW_ONLY_NUMERIC_POINT_CANDIDATE` | All required contracts pass and output remains non-executable. |
| `REVIEW_ONLY_NUMERIC_POINT_DEGRADED` | Some non-core point data is missing with explicit missing reason, requiring recheck and manual review. |
| `RECHECK_REQUIRED` | Recheck is mandatory before any downstream display or review. |
| `MANUAL_REVIEW_REQUIRED` | Manual review is mandatory. |

These statuses are not trade instructions, do not authorize order placement, and must not trigger automatic execution.

## Mandatory Safety Flags

The future validator output must force these flags:

- `reviewOnly = true`;
- `notTradeInstruction = true`;
- `manualReviewRequired = true`;
- `recheckRequired = true`;
- `riskActionGuardRequired = true`;
- `sourceTraceRequired = true`;
- `runtimeKlineContextRequired = true`;
- `dataQualityRequired = true`;
- `multiTimeframeRequired = true`;
- `incompleteSafe = true`;
- `failClosed = true` when blocked.

If any required safety flag is false, the output must be `BLOCKED_FAIL_CLOSED`.

## SourceTrace Validation

The future validator must check:

- `sourceTraceId` exists;
- `sourceOwner` exists;
- `sourceContractId` exists;
- symbol / timeframe match;
- `sourceValue`, `sourceValueLow`, and `sourceValueHigh` are valid or have `missingReason`;
- `observedAt` and `createdAt` are complete;
- `freshnessStatus` is `FRESH`;
- `runtimeKlineContextRef` exists;
- `riskActionGuardRef` exists;
- source was not derived from display text, score label, latest price only, or AI prose;
- source is not forged or untrusted.

Failure handling:

- missing / stale / unknown -> `INCOMPLETE`;
- forged / untrusted / Risk Action Guard bypass -> `BLOCKED_FAIL_CLOSED`.

## RuntimeKlineContext Validation

The future validator must check:

- `runtimeKlineContextId` exists;
- OHLCV window exists;
- OHLCV window is complete;
- `latestPrice` and `latestClose` are fresh;
- `latestPrice` and `latestClose` are not unresolved conflicts;
- `gapStatus` is not severe;
- `staleStatus` is not stale or unknown;
- wick / pin-bar is not treated as trend reversal;
- `liquidityState` is known;
- `stampedeState` is known;
- `sourceTraceRefs` match SourceTrace context;
- `riskActionGuardRef` exists.

Failure handling:

- missing / stale / unknown / incomplete -> `INCOMPLETE`;
- severe gap / confirmed stampede / severely degraded liquidity / confirmed abnormal data / blocking event risk -> `BLOCKED_FAIL_CLOSED`.

## DataQuality Validation

The future validator must check:

- `dataQualityContextId` exists;
- `dataQualityScore` exists;
- `dataQualityScore >= 70`;
- `hardThresholdPassed = true`;
- `sourceTraceCompletenessScore` exists;
- `runtimeKlineCompletenessScore` exists;
- `ohlcvCompletenessScore` exists;
- `freshnessScore` exists;
- `multiTimeframeConsistencyScore` exists;
- `missingFields` is empty;
- `degradedReasons` exists when degraded;
- `riskActionGuardRef` exists.

Failure handling:

- score missing / score < 70 / missing fields -> `INCOMPLETE`;
- hard threshold failed -> `BLOCKED_FAIL_CLOSED`;
- score 70-84 -> `REVIEW_ONLY_NUMERIC_POINT_DEGRADED` plus `RECHECK_REQUIRED` plus `MANUAL_REVIEW_REQUIRED`.

DataQuality cannot generate entry / stop / TP / RR and cannot replace SourceTrace, RuntimeKlineContext, MultiTimeframe, or Risk Action Guard.

## MultiTimeframe Validation

The future validator must check:

- `multiTimeframeContextId` exists;
- `requestedTimeframes` exist;
- `primaryTimeframe` exists;
- `confirmationTimeframes` exist;
- `higherTimeframe` exists;
- only-5m signal is not used as numeric point basis;
- high-timeframe conflict is resolved;
- lower-timeframe noise is not trade-inducing;
- wick-only signal is not used as trend reversal;
- strong reversal is confirmed before review;
- `sourceTraceRefs`, `runtimeKlineContextRefs`, and `dataQualityContextRef` match;
- `riskActionGuardRef` exists.

Failure handling:

- insufficient / missing / conflicted -> `INCOMPLETE`;
- trade-inducing conflict / low-timeframe noise inducing entry / strong reversal treated as direct reverse -> `BLOCKED_FAIL_CLOSED`.

## Risk Action Guard Validation

The future validator must check:

- `riskActionGuardContextId` exists;
- `overallRiskLevel` is known;
- `liquidityState` is known;
- `stampedeState` is known;
- `wickStatus` is known;
- `strongReversalStatus` is known;
- `highTimeframeConflictStatus` is known;
- `allowedReviewOnlyActions` exists;
- `forbiddenActions` exists;
- `manualReviewRequired = true`;
- `notTradeInstruction = true`;
- `reviewOnly = true`.

Failure handling:

- missing / unknown -> `INCOMPLETE`;
- bypass attempted / stampede confirmed / executable output attempted / `reviewOnly` false / `notTradeInstruction` false / `manualReviewRequired` false -> `BLOCKED_FAIL_CLOSED`.

## Entry Validation

Entry can enter review-only candidate status only when:

- SourceTrace passed;
- RuntimeKlineContext passed;
- DataQuality passed;
- MultiTimeframe passed;
- Risk Action Guard passed;
- entry source exists;
- entry zone exists or has `missingReason`;
- no buy / long / open / order semantics exist.

Entry candidate status is not buy, long, open, or order instruction.

## Stop Validation

Stop can enter review-only candidate status only when:

- invalidation source exists;
- stop context passed;
- no one-shot market cut exists;
- no automatic stop-loss semantics exist;
- no market close instruction exists.

Stop candidate status is not an automatic stop-loss order and not a market close suggestion.

## TP Validation

TP can enter review-only candidate status only when:

- TP source refs exist;
- TP ladder refs exist or `missingReason` exists;
- no sendable order semantics exist;
- no automatic take-profit semantics exist.

TP candidate status is not an automatic take-profit order and not a sendable order.

## RR Validation

RR can enter review-only candidate status only when:

- entry / stop / TP refs exist;
- calculation trace exists;
- RR is not used as standalone open condition;
- RR does not override Risk Action Guard.

RR candidate status is review-only analysis only.

## Forbidden Semantics

The future validator must reject output or messages containing executable trading semantics, including:

- buy;
- sell;
- long;
- short;
- open long;
- open short;
- close position;
- reverse;
- market close;
- market cut;
- order;
- execute;
- execution;
- auto-trade;
- auto trading;
- take-profit order;
- stop-loss order;
- send order;
- push opportunity during blocked state.

Any forbidden semantic must produce `BLOCKED_FAIL_CLOSED`.

## INCOMPLETE Conditions

The validator must return `INCOMPLETE` for at least:

- any required contract context missing;
- any required source ref missing;
- source stale;
- runtime stale;
- `dataQualityScore < 70`;
- multi-timeframe insufficient;
- Risk Action Guard missing;
- Watchlist Pool proof missing;
- entry source missing;
- stop source missing;
- TP source missing;
- RR calculation trace missing;
- manual review required but missing reason absent;
- partial candidate missing reason absent.

## BLOCKED_FAIL_CLOSED Conditions

The validator must return `BLOCKED_FAIL_CLOSED` for at least:

- validator bypass attempted;
- any required safety flag false;
- source forged or untrusted;
- data-quality hard threshold failed;
- severe OHLCV gap;
- confirmed stampede;
- severely degraded liquidity with executable output attempted;
- high-timeframe conflict trade-inducing;
- wick-only treated as trend reversal;
- strong reversal treated as direct reverse;
- forbidden executable semantics detected;
- external channel attempted;
- Push send attempted;
- order intent attempted;
- execution intent attempted;
- auto-trading attempted.

## Partial Candidate Handling

Partial point data must remain incomplete-safe:

- entry available but stop missing -> `INCOMPLETE` unless stop has explicit `missingReason`;
- stop available but entry missing -> `INCOMPLETE` unless entry has explicit `missingReason`;
- TP missing -> `REVIEW_ONLY_NUMERIC_POINT_DEGRADED` only if entry / stop are valid and TP `missingReason` exists;
- RR missing -> `REVIEW_ONLY_NUMERIC_POINT_DEGRADED` only if RR `missingReason` exists;
- any missing reason absent -> `INCOMPLETE`;
- any executable semantic in partial output -> `BLOCKED_FAIL_CLOSED`.

## Watchlist And Display Slots Boundary

Watchlist Pool proof is a validator input.

Display Slots are not a push-candidate boundary.

The validator must not treat Display Slots as Watchlist Pool.

`watchlistPoolProof` missing -> `INCOMPLETE`.

Stampede confirmed -> opportunity push blocked.

External channel must be separately authorized.

P318 does not connect Push, Telegram, email, webhook, app notification, local notification, message rendering, or message send.
