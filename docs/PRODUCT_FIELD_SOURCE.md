# Trade Model V1 Product Field Source Matrix

Status: `P0_PRODUCT_BASELINE_FREEZE_CANDIDATE`

This matrix maps product fields to real or intended authoritative sources. “Implemented” means a current read/model path was found; it is not proof of full product acceptance. `GAP` means the product requires the field but the current source, contract, or end-to-end proof is incomplete. Authority: `docs/PRODUCT_SOURCE_OF_TRUTH.md`.

## 1. Reading Rules

- Exact identities remain strings at the browser/network boundary when JavaScript precision could be lost.
- A service name documents the current or designated domain owner; it does not authorize a new API in this P0 task.
- “Cadence” is the product expectation. Current runtime scheduling must be verified again in the delivery package.
- Cache never converts stale or failed data into current success.
- Public/private classification is a hard boundary, not a display preference.

### Eight-score implementation boundary

The product contract is `real raw data -> normalized evidence -> scoring model/rules -> eight score results`. The current existence of `GET /api/score/list` does not prove that product chain is complete: the controller constructs a `MarketEnvironmentVO` from `symbol` and `timeframe`, and `ScoreServiceImpl.buildScoreListFromEnvironment` supplies an empty `AssetAnalysisVO` to score calculations that include fixed base/default values and light-rule adjustments. No current evidence proves complete per-dimension inputs, real-market calibration, or a stable analysis-linked snapshot.

## 8. Known Source Gaps

1. My/Profile has no frozen complete real-field contract; unsupported Figma examples must remain hidden or unavailable.
2. Full Home multi-timeframe and concise support/opposition summaries need an end-to-end exact-analysis proof.
3. ExecutionPlan read identity and complete source trace need product-level verification independent of generation endpoints.
4. Three-AI evidence package, deployed model metadata, conflict calibration, and real failure fallback need real-run evidence.
5. Position monitor real market cadence, wick/reversal scenarios, account-risk calibration, and alert timeliness need real or historical replay validation.
6. Message/Push backend projections exist, but the Message Center and Push Detail UI have not passed product/design/real-scenario acceptance.
7. iPhone has a merged Xcode SwiftUI/WKWebView foundation with simulator build, tests, install, launch, and Session/WKWebView compatibility evidence. Real-device install/login, real Session/Cookie/CSRF lifecycle, production-server networking, background recovery, final size/interaction acceptance, and distribution remain unvalidated.
8. Operational status endpoints are numerous; production dashboards, alerting, log retention, and incident evidence remain incomplete.
