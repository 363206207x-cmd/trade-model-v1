## 4. Future External Channel Scope

A future external channel may only be introduced after separate authorization.

The first allowed shape must be a disabled no-op Java skeleton.

That future skeleton must start:

- disabled-by-default
- fail-closed
- audit-only
- review-only
- no-message-sending
- no-credential
- no-live-provider-call

The future external channel may only represent internal review metadata about whether an external channel remains disabled.

It must not connect a real Telegram, email, webhook, app notification, or local notification channel. It must not select a provider, read credentials, render final message text, send a message, activate scheduler behavior, connect API / dashboard, read runtime / live / external data, upgrade Readiness, generate point levels, or create trading actions.
