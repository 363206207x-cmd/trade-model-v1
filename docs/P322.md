# P322 ReviewOnly Numeric Point Assembler Java Skeleton

## Purpose

P322 belongs to the Readiness / Point Mainline.

P322 follows P321 `NUMERIC_POINT_SAFETY_VALIDATOR_JAVA_SKELETON`.

P322 adds a minimal plain Java `ReviewOnlyNumericPointProposalAssembler` skeleton and targeted tests.

The assembler moves explicit source-owned review-only numeric point fields into `ReviewOnlyNumericPointProposalDTO` and immediately runs `NumericPointSafetyValidator`.

P322 is not point generation, not service wiring, not dashboard runtime integration, not external push, and not order / execution / auto-trading.

## What P322 Adds

P322 adds:

- `src/main/java/org/example/trademodel/assembler/point/ReviewOnlyNumericPointProposalAssembler.java`;
- `src/test/java/org/example/trademodel/assembler/point/ReviewOnlyNumericPointProposalAssemblerTest.java`.

The assembler exposes:

- `assemble(AssemblyInput input)`;
- nested `AssemblyInput`;
- nested `AssembledReviewOnlyNumericPoint`.

`AssembledReviewOnlyNumericPoint` carries:

- `ReviewOnlyNumericPointProposalDTO proposal`;
- `NumericPointSafetyValidator.ValidationResult validationResult`.

## Assembly Boundary

The assembler only moves explicit input values.

It does not calculate entry, stop, TP, RR, final direction, or any executable signal.

It does not infer values from latest price, latest close, volatility, score, label, AI prose, dashboard text, or market data.

It does not provide defaults for missing point values.

It does not decide whether to trade.

It does not send messages.

It does not call external APIs.

## Status Handling

The assembler maps explicit requested status into DTO factories:

- null input -> `INCOMPLETE`;
- `BLOCKED_FAIL_CLOSED` -> `blockedFailClosed(...)`;
- `REVIEW_ONLY_NUMERIC_POINT_DEGRADED` -> `degraded(...)`;
- `REVIEW_ONLY_NUMERIC_POINT_CANDIDATE` -> `reviewOnlyCandidate(...)`;
- any other status -> `incomplete(...)`.

Every assembled proposal is validated by `NumericPointSafetyValidator`.

## Point Field Boundary

The assembler can carry explicit:

- `EntryReviewPoint`;
- `StopReviewPoint`;
- `TakeProfitReviewLevel` list;
- `RiskRewardReviewField`.

These fields are moved only. They may be null.

Missing fields are resolved only by validator status: `INCOMPLETE`, degraded review-only, or blocked fail-closed.

The assembler does not inspect行情, does not judge direction, and does not decide execution.

## Validation Scope

The targeted test verifies:

- null and incomplete inputs remain incomplete;
- candidate inputs with all refs and point fields validate as review-only candidates;
- candidate inputs missing refs or point fields validate as incomplete;
- degraded input with missing reason validates as degraded;
- blocked input with blocked reason validates as fail-closed;
- forbidden executable semantics are blocked by the validator;
- assembler calls validator and returns both proposal and validation result;
- explicit BigDecimal values are preserved without calculation;
- null point fields do not throw;
- assembler has no Spring annotations, provider clients, service/controller/mapper/repository/scheduler refs, external channel refs, or order / execution / auto-trading refs.
