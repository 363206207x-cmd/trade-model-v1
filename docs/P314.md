# P314 RuntimeKlineContext Numeric Point Contract Plan

## Purpose

P314 belongs to the Readiness / Point Mainline.

P314 is a docs-only RuntimeKlineContext contract plan after P313 `SOURCETRACE_NUMERIC_POINT_CONTRACT_PLAN`.

It defines which runtime kline windows and market context must exist before any future entry / stop / TP / RR numeric value can enter a review-only numeric point proposal.

P314 does not create Java DTOs, does not implement numeric point proposal, does not generate real entry / stop / TP / RR, does not connect dashboard runtime, does not connect external channels, and does not connect order / execution / auto-trading.

## What P314 Is Not

P314 is docs-only.

P314 does not raise Production Runtime Progress.

P314 does not mean RuntimeKlineContext Java DTO is complete.

P314 does not mean numeric point proposal is implemented.

P314 does not mean real entry / stop / TP / RR are complete.

P314 does not mean dashboard runtime integration.

P314 does not mean external push.

P314 does not mean order, execution, or auto-trading.

P314 does not allow direct order placement after merge.

## RuntimeKlineContext Contract Boundary

RuntimeKlineContext is the runtime market observation contract that a future numeric point source must reference.

It answers:

- which symbol, market, and timeframe own the observed window;
- whether the OHLCV window is complete enough for review;
- whether latest price and latest close are fresh and consistent;
- whether wick, pin-bar, liquidity, stampede, multi-timeframe, event, or abnormal data context blocks numeric review;
- which Risk Action Guard result reviewed the context.

RuntimeKlineContext can support only review-only numeric proposal. It cannot support buy, sell, long, short, open, close, reverse, order, execution, or auto-trading action.

Every future numeric point runtime context must include at least:

| Field | Required meaning |

| `market` | Market or venue context used by the source. |
| `requestedTimeframes` | Timeframes requested for review. |
| `owningTimeframe` | Timeframe that owns the numeric point context. |
| `observedAt` | Time the runtime context was observed. |
| `createdAt` | Time this context was created. |
| `latestPrice` | Nullable realtime or near-realtime observed price. |
| `latestClose` | Nullable completed-kline close. |
| `latestPriceObservedAt` | Timestamp for latest price observation. |
| `klineWindowStart` | Start of the owning OHLCV window. |
| `klineWindowEnd` | End of the owning OHLCV window. |
| `ohlcvWindowRef` | Reference to the OHLCV window or fixture. |
| `ohlcvCompletenessStatus` | Complete, incomplete, missing, or unknown. |
| `missingCandleCount` | Number of missing candles in the window. |
| `gapStatus` | No gap, gap, severe gap, or unknown. |
| `staleStatus` | Fresh, stale, unknown, gap, conflicted, or abnormal. |
| `dataQualityScore` | Runtime data quality score. |
| `wickStatus` | Wick / spike context. |
| `wickConfirmationStatus` | Confirmed, unconfirmed, not applicable, or unknown. |
| `pinBarStatus` | Pin-bar context. |
| `liquidityState` | Normal, degraded, severely degraded, unknown, or blocked. |

| `missingReason` | Required when required context is unavailable. |

## Latest Price And Latest Close Boundary

`latestPrice` can only represent a realtime or near-realtime price observation point.

`latestClose` can only represent a completed kline close.

Entry / stop / TP source must not be derived only from `latestPrice`.

`latestPrice` cannot replace an OHLCV window.

`latestClose` cannot replace realtime risk state.

If `latestPrice` and `latestClose` conflict, the context must become `INCOMPLETE` or wait for confirmation.

If only `latestPrice` remains and no kline window exists, future numeric point proposal must not generate or display numeric point values.

## Kline Window Definition

`klineWindowStart` and `klineWindowEnd` define the owned observation window for the numeric point context.

For a completed kline window:

- `klineWindowStart` must be earlier than `klineWindowEnd`;
- `ohlcvWindowRef` must identify the window;
- `ohlcvCompletenessStatus` must be complete;
- `missingCandleCount` must be zero or within the review-only tolerance;
- `gapStatus` must not be severe;
- `staleStatus` must not be stale or unknown.

If the window is missing, incomplete, stale, conflicted, or severely gapped, it can support only a missing reason or fail-closed reason.

## OHLCV Missing Handling

Missing OHLCV context means `INCOMPLETE`.

Incomplete OHLCV context means `INCOMPLETE`.

Severe OHLCV gap means `BLOCKED_FAIL_CLOSED`.

Unknown OHLCV completeness means `INCOMPLETE`.

OHLCV derived only from display text, AI prose, candidate label, score label, or latest price is invalid and must not support numeric values.

## Entry RuntimeKlineContext Contract

Entry numeric point context must include:

- owning timeframe OHLCV window;
- entry-related `klineWindowStart` / `klineWindowEnd`;
- `latestPriceObservedAt`;
- source-owned boundary / zone context;
- wick / pin-bar confirmation context;
- multi-timeframe non-conflict status;
- liquidity known status;
- stampede known status;
- `dataQualityScore`;
- `riskActionGuardRef`.

Entry context must not come only from latest price, AI prose, dashboard text, candidate label, or score label.

Entry context is not buy, long, open, or order instruction.

## Stop RuntimeKlineContext Contract

Stop numeric point context must include:

- invalidation owning timeframe;
- swing / structural boundary window;
- OHLCV window completeness;
- volatility / wick abnormality status;
- `gapStatus`;
- `staleStatus`;
- `dataQualityScore`;
- `liquidityState`;
- `stampedeState`;
- `riskActionGuardRef`.

Stop context is not an automatic stop-loss order and not a market close suggestion.

## TP RuntimeKlineContext Contract

TP numeric point context must include:

- TP owning timeframe;
- resistance / support / liquidity target context;
- OHLCV window completeness;
- multi-timeframe non-conflict status;
- `liquidityState`;
- `stampedeState`;
- `dataQualityScore`;
- `riskActionGuardRef`.

TP context is not an automatic take-profit order and not a sendable order.

## RR RuntimeKlineContext Contract

RR numeric review field must include:

- entry runtime context ref;
- stop runtime context ref;
- TP runtime context ref;
- same-symbol consistency;
- compatible timeframe consistency;
- data-quality consistency;
- calculation trace;
- `missingReason` when any input context is incomplete.

RR cannot be used alone as an open-position condition.

## Wick, Pin-Bar, Liquidity, Stampede, Multi-Timeframe, Event, And Abnormal Data Context

Wick and pin-bar context enters the contract through `wickStatus`, `wickConfirmationStatus`, and `pinBarStatus`.

Unconfirmed wick or pin-bar behavior cannot support numeric points and must remain `INCOMPLETE`.

Liquidity context enters through `liquidityState` and `liquiditySourceRef`.

Unknown liquidity means `INCOMPLETE`; severely degraded liquidity means `BLOCKED_FAIL_CLOSED`.

Stampede context enters through `stampedeState` and `stampedeSourceRef`.

Unknown stampede state means `INCOMPLETE`; confirmed stampede means `BLOCKED_FAIL_CLOSED`.

Multi-timeframe context enters through `multiTimeframeState` and `higherTimeframeConflictStatus`.

Unresolved higher-timeframe conflict means `INCOMPLETE`; trade-inducing conflict means `BLOCKED_FAIL_CLOSED`.

Event and abnormal data context enters through `eventRiskStatus` and `abnormalDataStatus`.

Unknown event risk during an active event window means `INCOMPLETE`; blocking event risk or confirmed abnormal data means `BLOCKED_FAIL_CLOSED`.

## Freshness And Stale Rules

Runtime context freshness uses these states:

- `FRESH`: RuntimeKlineContext matches the decision window, OHLCV is complete, and timestamps are valid.
- `STALE`: context exceeds the allowed window, or latest price / close is expired.
- `UNKNOWN`: timestamp, OHLCV window, or freshness cannot be determined.
- `GAP`: kline window contains missing candles or discontinuity.
- `CONFLICTED`: multi-timeframe, latestPrice/latestClose, or source traces conflict.
- `ABNORMAL`: event risk, abnormal data, wick / pin-bar, or stampede makes context unsafe for direct numeric review.

Freshness outcomes:

- `STALE` -> `INCOMPLETE`.
- `UNKNOWN` -> `INCOMPLETE`.
- `GAP` -> `INCOMPLETE`; severe gap -> `BLOCKED_FAIL_CLOSED`.
- `CONFLICTED` -> `INCOMPLETE` or `BLOCKED_FAIL_CLOSED` when trade-inducing.
- `ABNORMAL` -> Risk Action Guard review; if guard does not pass, `BLOCKED_FAIL_CLOSED`.

## Context That Can Only Support Missing Reason

RuntimeKlineContext can only support missing reason, not numeric display, when:

- no OHLCV window exists;
- only latest price is available;
- latest price and latest close conflict;
- kline window is stale or unknown;
- wick / pin-bar is unconfirmed;
- liquidity or stampede state is unknown;
- multi-timeframe context is missing or conflicted;
- event / abnormal data context is unknown during an active event window;
- source traces are missing or mismatched;
- Risk Action Guard ref is missing.

## INCOMPLETE Conditions

Future numeric point proposal must stay `INCOMPLETE` when any condition is true:

- `runtimeKlineContextId` missing;
- symbol mismatch;
- market mismatch;
- `requestedTimeframes` missing;
- `owningTimeframe` missing;
- `observedAt` missing;
- `latestPriceObservedAt` missing;
- `klineWindowStart` / `klineWindowEnd` missing;
- OHLCV window missing;
- OHLCV incomplete;
- missing candles;
- `gapStatus` unknown;
- `staleStatus` is `STALE`;
- `staleStatus` is `UNKNOWN`;
- `dataQualityScore` missing;
- `dataQualityScore` below threshold;
- wick status unknown;
- wick confirmation missing;
- `liquidityState` unknown;
- `stampedeState` unknown;
- `multiTimeframeState` conflicted;
- higher timeframe conflict unresolved;
- `eventRiskStatus` unknown when event window is active;
- `abnormalDataStatus` unknown;
- `sourceTraceRefs` missing;
- `riskActionGuardRef` missing.

`INCOMPLETE` may explain unavailable context but must not generate numeric values.

## BLOCKED_FAIL_CLOSED Conditions

Future numeric point proposal must become `BLOCKED_FAIL_CLOSED` when any condition is true:

- RuntimeKlineContext forged / untrusted;
- source trace and runtime context mismatch;
- data quality hard threshold failed;
- severe OHLCV gap;
- stampede confirmed;
- liquidity severely degraded;
- abnormal data confirmed;
- event risk blocks point review;
- higher timeframe conflict would induce immediate reverse;
- wick / pin-bar treated as trend reversal without confirmation;
- context attempts to bypass Risk Action Guard;
- context implies buy / sell / long / short;
- context implies order intent;
- context implies execution intent;
- context implies auto-trading.

`BLOCKED_FAIL_CLOSED` must never be rendered as a trade-ready numeric point.

## Risk Action Guard Integration

RuntimeKlineContext cannot bypass Risk Action Guard.

Risk Action Guard ref must enter runtime context before future numeric point review.

High risk does not mean immediate stop.

High risk does not mean immediate reverse.

High risk does not mean immediate open.

Strong reversal does not mean direct reverse.

Wick / pin-bar behavior does not mean trend reversal.

Stampede state blocks opportunity push.

Degraded liquidity does not recommend one-shot market cutting.

Even a complete RuntimeKlineContext cannot become a trading action.

## Final Conclusion

P314 moves the planning state from `SOURCETRACE_NUMERIC_POINT_CONTRACT_PLAN` to `RUNTIME_KLINE_CONTEXT_NUMERIC_POINT_CONTRACT_PLAN`.

It defines the minimum runtime kline and market context that future numeric point values must satisfy. It keeps all point work review-only, incomplete-safe, fail-closed, and blocked from executable trading semantics.
