# P320 ReviewOnlyNumericPointProposalDTO Java Skeleton

## Purpose

P320 belongs to the Readiness / Point Mainline.

P320 is a minimal Java DTO skeleton after P319 `NUMERIC_POINT_FIXTURE_MATRIX_PLAN`.

It adds `ReviewOnlyNumericPointProposalDTO` as a plain Java DTO for future review-only numeric entry / stop / TP / RR proposal candidates and a targeted DTO test.

P320 is not a validator, not an assembler, not a service, not real point generation, not dashboard runtime integration, not external push, and not order / execution / auto-trading.

## What P320 Adds

P320 adds:

- `src/main/java/org/example/trademodel/dto/point/ReviewOnlyNumericPointProposalDTO.java`;
- `src/test/java/org/example/trademodel/dto/point/ReviewOnlyNumericPointProposalDTOTest.java`.

The DTO supports:

- `INCOMPLETE`;
- `BLOCKED_FAIL_CLOSED`;
- `REVIEW_ONLY_NUMERIC_POINT_CANDIDATE`;
- `REVIEW_ONLY_NUMERIC_POINT_DEGRADED`;
- `RECHECK_REQUIRED`;
- `MANUAL_REVIEW_REQUIRED`.

The DTO includes nested value objects for:

- entry review point;
- stop review point;
- TP review level;
- RR review field.

## Safety Contract

Every factory keeps these flags true:

- `reviewOnly`;
- `notTradeInstruction`;
- `manualReviewRequired`;
- `recheckRequired`;
- `riskActionGuardRequired`;
- `sourceTraceRequired`;
- `runtimeKlineContextRequired`;
- `dataQualityRequired`;
- `multiTimeframeRequired`;
- `incompleteSafe`.

`blockedFailClosed(...)` sets `failClosed = true`.

The DTO does not expose setters or builders that can turn off safety flags.

The DTO defensively copies list fields on input and output.

## Numeric Field Boundary

The DTO can carry nullable future review-only numeric fields, such as:

- entry price / entry zone;
- stop price / stop zone;
- TP price / TP zone;
- RR value.

These fields are nullable and incomplete-safe.

The DTO does not calculate numeric fields.

The DTO does not infer numeric fields from latest price, score, label, AI prose, or dashboard text.

The DTO does not generate default points.

The DTO does not turn BigDecimal fields into trading instructions.

The DTO does not represent executable entry / stop / TP / RR.

## Validation Scope

The targeted test verifies:

- safety flags are forced true;
- blocked status is fail-closed;
- incomplete and degraded factories require reasons;
- candidate output only carries explicit input fields;
- entry / stop / TP / RR can remain null;
- list fields are defensively copied;
- no setter / builder / boolean factory parameter can disable safety flags;
- no Spring annotation or forbidden dependency exists;
- status and public reason outputs do not contain forbidden executable semantics.
