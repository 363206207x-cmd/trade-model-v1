# P286 Market-Read Request Contract Authorization Gate

P286 is a docs-only Scope Pack for PR #691 / Issue #690.

P286 defines the future `MarketReadRequestDTO` contract plan, safety defaults, source boundary, and DTO authorization gate. It does not implement Java, tests, DTOs, market-read wiring, runtime data reads, scan output, scoring, Candidate workflow, Push, Readiness, point generation, or trading behavior.

## 1. P285 Closure Baseline

P285 merged as `c64c8b8`.

P285 was docs-only / boundary-only. P285 kept market-read Java blocked and only audited market-read boundary, Watchlist Pool proof source, and protected real scan input assembly authorization shape.

## 2. P286 Scope

P286 only defines future `MarketReadRequestDTO` planning:

- field plan;
- safety defaults;
- source boundary;
- DTO skeleton authorization gate;
- market-read Java still blocked;

## 3. Future MarketReadRequestDTO Field Plan

Future `MarketReadRequestDTO` fields to consider:

- `symbol`;
- `requestId`;
- `sourceContractId`;
- `watchlistPoolProof`;
- `watchlistConfigVersion`;
- `requestedScanReason`;
- `requestedTimeframes`;
- `scanTimestamp`;
- `dataAvailabilityExpectation`;
- `stalePolicy`;
- `missingDataPolicy`;
- `riskBlockers`;
- `reviewOnly` flag;
- `notTradeInstruction` flag;
- `guardValidationStatus`;
- `blockingReasons`.

The request must originate only from a GuardValidator-approved `RealScanInputContractDTO`. If the source contract is null, incomplete, blocked, missing Watchlist Pool proof, not a Watchlist Pool member, or not review-only, no future market-read request may be assembled.

## 4. Safety Defaults

Future `MarketReadRequestDTO` safety defaults must preserve:

- `reviewOnly=true`;
- `notTradeInstruction=true`;
- manual review required by source contract;
- fail-closed stale policy;
- fail-closed missing-data policy;
- empty or missing timeframes are blocked;
- missing proof is blocked;
- missing source contract is blocked;
- missing timestamp is blocked;
- blocking reasons are carried forward.

The request cannot produce scan output, score, Candidate, Push, Readiness, point generation, or trading action.

## 5. Source Boundary

Future `MarketReadRequestDTO` source boundary:

- only a GuardValidator-approved `RealScanInputContractDTO` may be the source;
- Watchlist Pool proof must be carried from the approved source contract;
- Watchlist config version must be carried from the approved source contract;
- requested scan reason and requested timeframes must be carried from the approved source contract;
- risk blockers and blocking reasons must be preserved;
- review-only and not-trade-instruction flags must be preserved.

Display Slots / 默认六币 cannot be scan universe or batch universe and cannot prove scan eligibility. Watchlist Pool remains the scan candidate boundary.

## 6. Fail-Closed Behavior

Future request assembly must fail closed when any required field/source/proof/timeframe/timestamp/stale policy/missing-data policy is missing or invalid.

Fail-closed means:

- no `MarketQuoteClient` / `BinanceMarketQuoteClient` wiring;
- no runtime/live/external data read;
- no scan output creation;
- no real scan loop;
- no production ScanScore computation;
- no Candidate production workflow;
- no Opportunity Push execution;
- no scheduler/API/dashboard wiring;
- no external channel behavior / provider credentials / live provider call / message rendering / sending;
- no Readiness / point generation / entry-stop-TP-RR / order / execution / auto-trading.

## 7. Authorization Gate

Future DTO skeleton authorization conditions must be defined in a later package before Java can begin. P286 keeps Java blocked.

Future authorization must decide whether P287 should remain another docs-only gate or may implement a DTO skeleton. Future recommended next package after P286 should be P287 Market-Read Request DTO Authorization Gate or DTO Skeleton, depending on whether another docs-only gate is needed.
