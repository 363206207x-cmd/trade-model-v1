# P319 Numeric Point Fixture Matrix Plan

## Purpose

P319 belongs to the Readiness / Point Mainline.

P319 is a docs-only Numeric Point Fixture Matrix plan after P318 `NUMERIC_POINT_SAFETY_VALIDATOR_PLAN`.

It defines the future positive, incomplete, degraded, partial, fail-closed, forbidden semantics, cross-contract, Watchlist / Display Slots, external channel, and order / execution / auto-trading fixture matrix that must exist before Java DTO / validator / assembler skeleton work can safely start.

P319 does not create Java tests, does not create Java DTOs, does not create validator classes, does not implement numeric point proposal, does not generate real entry / stop / TP / RR, does not connect dashboard runtime, does not connect external channels, and does not connect order / execution / auto-trading.

## What P319 Is Not

P319 is docs-only.

P319 does not raise Production Runtime Progress.

P319 does not mean Java tests are complete.

P319 does not mean Safety Validator Java is complete.

P319 does not mean numeric point proposal is implemented.

P319 does not mean real entry / stop / TP / RR are complete.

P319 does not mean dashboard runtime integration.

P319 does not mean external push.

P319 does not mean order, execution, or auto-trading.

P319 does not allow direct order placement after merge.

## Fixture Matrix Responsibility Boundary

The future Numeric Point Fixture Matrix is a contract for test data, expected statuses, and negative safety cases.

It must prove future review-only numeric point DTOs, validators, and assemblers cannot accidentally turn entry / stop / TP / RR into executable trading instructions.

It should define fixture categories, fixture payload expectations, expected validator outcomes, and package boundaries for future Java tests.

It must not create test classes in P319.

It must not generate numeric values in P319.

It must not authorize executable point generation.

## Fixture Categories

Future fixtures must include at least:

- Positive review-only fixtures;
- Incomplete fixtures;
- Blocked fail-closed fixtures;
- Degraded review-only fixtures;
- Partial candidate fixtures;
- Forbidden semantics fixtures;
- Watchlist / Display Slots boundary fixtures;
- External channel negative fixtures;
- Order / execution / auto-trading negative fixtures;
- Cross-contract consistency fixtures.

## Partial Candidate Fixtures

Partial candidate fixtures must cover at least:

| # | Fixture requirement | Expected result |
|---:|---|---|
| 1 | entry valid but stop missing | `INCOMPLETE` unless stop has explicit missingReason. |
| 2 | stop valid but entry missing | `INCOMPLETE` unless entry has explicit missingReason. |
| 3 | entry / stop valid but TP missing | Degraded or incomplete-safe only when TP missingReason exists. |
| 4 | entry / stop / TP valid but RR missing | Degraded or incomplete-safe only when RR missingReason exists. |
| 5 | TP ladder partially missing | Degraded or incomplete-safe only when missingReason exists. |
| 6 | missingReason present | Degraded or incomplete-safe. |
| 7 | missingReason absent | `INCOMPLETE`. |
| 8 | partial output includes forbidden semantics | `BLOCKED_FAIL_CLOSED`. |

Partial output must never hide missing source, missing stop, missing TP, or missing RR.

## Forbidden Semantics Fixtures

Forbidden semantics fixtures must cover any output or message containing:

- buy;
- sell;
- long;
- short;
- open long;
- open short;
- close position;
- reverse;
- market close;
- market cut;
- order;
- execute;
- execution;
- auto-trade;
- auto trading;
- take-profit order;
- stop-loss order;
- send order;
- push opportunity during blocked state.

Expected result:

`BLOCKED_FAIL_CLOSED`

These fixture names are allowed in test data and docs, but any future validator output containing them as actionable semantics must fail closed.

Watchlist / Display Slots boundary fixtures must cover at least:

| # | Fixture requirement | Expected result |
|---:|---|---|
| 1 | watchlistPoolProof present | May continue if all other contracts pass. |
| 2 | watchlistPoolProof missing | `INCOMPLETE`. |
| 3 | Display Slots present but Watchlist Pool missing | `INCOMPLETE`. |
| 4 | Display Slots treated as Watchlist Pool | `BLOCKED_FAIL_CLOSED`. |

Watchlist Pool proof is the candidate boundary.

Display Slots are display-only and must not become candidate source proof.
