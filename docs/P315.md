# P315 DataQuality Numeric Point Contract Plan

## Purpose

P315 belongs to the Readiness / Point Mainline.

P315 is a docs-only DataQuality contract plan after P314 `RUNTIME_KLINE_CONTEXT_NUMERIC_POINT_CONTRACT_PLAN`.

It defines which data-quality scores, thresholds, completeness checks, source freshness checks, runtime kline completeness checks, multi-source consistency checks, degradation rules, and blocking rules must exist before any future entry / stop / TP / RR numeric value can enter a review-only numeric point proposal.

P315 does not create Java DTOs, does not implement numeric point proposal, does not generate real entry / stop / TP / RR, does not connect dashboard runtime, does not connect external channels, and does not connect order / execution / auto-trading.

## What P315 Is Not

P315 is docs-only.

P315 does not raise Production Runtime Progress.

P315 does not mean DataQuality Java DTO is complete.

P315 does not mean numeric point proposal is implemented.

P315 does not mean real entry / stop / TP / RR are complete.

P315 does not mean dashboard runtime integration.

P315 does not mean external push.

P315 does not mean order, execution, or auto-trading.

P315 does not allow direct order placement after merge.

## DataQuality Contract Boundary

DataQuality is the review-only gate that summarizes whether SourceTrace and RuntimeKlineContext inputs are complete, fresh, consistent, and safe enough to consider a future source-owned numeric point proposal.

DataQuality cannot generate entry / stop / TP / RR.

DataQuality cannot replace SourceTrace.

DataQuality cannot replace RuntimeKlineContext.

DataQuality cannot replace Risk Action Guard.

DataQuality can only support:

- high-quality review-only numeric proposal consideration;
- degraded review-only numeric proposal consideration with extra manual review / recheck;
- `INCOMPLETE` missing reason;
- `BLOCKED_FAIL_CLOSED` blocked reason.

Every future numeric point data quality context must include at least:

| Field | Required meaning |

| `dataQualityGrade` | Grade such as HIGH, DEGRADED, INCOMPLETE, BLOCKED, or UNKNOWN. |
| `hardThresholdPassed` | False means `BLOCKED_FAIL_CLOSED`. |
| `warningThresholdPassed` | False means degraded review-only / recheck required, not executable output. |
| `sourceTraceCompletenessScore` | SourceTrace completeness subscore. |
| `runtimeKlineCompletenessScore` | RuntimeKlineContext completeness subscore. |
| `ohlcvCompletenessScore` | OHLCV window completeness subscore. |
| `freshnessScore` | Freshness / stale subscore. |
| `multiTimeframeConsistencyScore` | Multi-timeframe consistency subscore. |
| `liquidityQualityScore` | Liquidity quality subscore. |
| `stampedeRiskScore` | Stampede risk subscore. |
| `wickRiskScore` | Wick / pin-bar risk subscore. |
| `eventRiskScore` | Event risk subscore. |
| `abnormalDataScore` | Abnormal data subscore. |

## DataQuality Score Definition

`dataQualityScore` is a review-only aggregate quality score. It summarizes the completeness and freshness of:

- SourceTrace quality;
- RuntimeKlineContext quality;
- OHLCV completeness;
- latest price / latest close freshness;
- multi-timeframe consistency;
- liquidity state;
- stampede state;
- wick / pin-bar confirmation;
- event risk state;
- abnormal data state;
- Risk Action Guard reference presence.

It is not a score for buying, selling, going long, going short, opening, closing, reversing, ordering, executing, or auto-trading.

## Threshold Rules

The future DataQuality contract must use these thresholds:

- `dataQualityScore >= 85`: may enter review-only numeric proposal consideration, but SourceTrace, RuntimeKlineContext, and Risk Action Guard must still pass.
- `70 <= dataQualityScore < 85`: may enter degraded review-only proposal consideration only with extra manual review and recheck.
- `dataQualityScore < 70`: must be `INCOMPLETE`.
- `hardThresholdPassed = false`: must be `BLOCKED_FAIL_CLOSED`.
- `warningThresholdPassed = false`: must not execute; it may only downgrade to review-only / recheck required.

`dataQualityScore` by itself cannot generate entry / stop / TP / RR, cannot replace source trace, and cannot replace runtime kline context.

## SourceTrace Quality Rules

SourceTrace quality must check:

- `sourceTraceId` exists;
- `sourceOwner` exists;
- `sourceContractId` exists;
- symbol / timeframe matches;
- `sourceValue` is trustworthy or has a missing reason;
- `observedAt` / `createdAt` are complete;
- `freshnessStatus` is `FRESH`;
- source-level `dataQualityScore` is consistent with the DataQuality context;
- `runtimeKlineContextRef` exists;
- `riskActionGuardRef` exists;
- source is not derived from display text, score label, latest price, or AI prose.

Any forged source trace, untrusted source trace, or source trace that bypasses Risk Action Guard must become `BLOCKED_FAIL_CLOSED`.

## RuntimeKlineContext Quality Rules

RuntimeKlineContext quality must check:

- `runtimeKlineContextId` exists;
- OHLCV window is complete;
- `latestPrice` / `latestClose` are fresh;
- `latestPrice` / `latestClose` do not conflict;
- `gapStatus` is not severe;
- `staleStatus` is not `STALE` or `UNKNOWN`;
- wick confirmation is complete when wick context matters;
- `liquidityState` is not unknown or severely degraded;
- `stampedeState` is not unknown or confirmed;
- `eventRiskStatus` is not active / blocking without review;
- `abnormalDataStatus` is not confirmed / blocking;
- `riskActionGuardRef` exists.

Severe OHLCV gap, confirmed stampede, severely degraded liquidity, confirmed abnormal data, or blocking event risk must become `BLOCKED_FAIL_CLOSED`.

## OHLCV, Freshness, Liquidity, Stampede, Wick, Event, And Abnormal Data Quality

OHLCV incompleteness lowers DataQuality and may force `INCOMPLETE`.

Missing OHLCV window means `INCOMPLETE`.

Severe OHLCV gap means `BLOCKED_FAIL_CLOSED`.

Stale source trace or stale runtime context means `INCOMPLETE`.

Unresolved latestPrice / latestClose conflict means `INCOMPLETE`.

Unknown liquidity quality means `INCOMPLETE`; severely degraded liquidity means `BLOCKED_FAIL_CLOSED`.

Unknown stampede risk means `INCOMPLETE`; confirmed stampede means `BLOCKED_FAIL_CLOSED`.

Missing wick confirmation means `INCOMPLETE`; treating wick / pin-bar as trend reversal without confirmation means `BLOCKED_FAIL_CLOSED`.

Unknown event risk during an active event window means `INCOMPLETE`; blocking event risk means `BLOCKED_FAIL_CLOSED`.

Unknown abnormal data state means `INCOMPLETE`; confirmed abnormal data means `BLOCKED_FAIL_CLOSED`.

## Multi-Timeframe Quality Rules

Multi-timeframe quality must check:

- all requested timeframes are present;
- owning timeframe is present;
- higher timeframe conflict is resolved;
- source trace timeframe and runtime context timeframe are compatible;
- timeframe conflicts do not imply immediate reverse.

Unknown multi-timeframe consistency means `INCOMPLETE`.

Trade-inducing multi-timeframe conflict means `BLOCKED_FAIL_CLOSED`.

## DataQuality That Can Only Support Missing Reason

DataQuality can only support missing reason, not numeric values, when:

- score is missing;
- score is below 70;
- grade is unknown;
- source trace quality is incomplete;
- runtime kline quality is incomplete;
- OHLCV completeness is unknown;
- freshness cannot be established;
- liquidity quality is unknown;
- stampede risk is unknown;
- wick confirmation is missing;
- event or abnormal data status is unknown in an active risk window;
- Risk Action Guard ref is missing;
- missing fields are non-empty.

## Review-Only Numeric Proposal But Still Not Executable

Future review-only numeric proposal consideration may happen only when:

- `dataQualityScore >= 85`, or degraded 70-84 with extra manual review and recheck;
- hard threshold passes;
- SourceTrace refs pass contract checks;
- RuntimeKlineContext passes contract checks;
- Risk Action Guard ref exists;
- no blocking reason exists.

Even then, the output remains `reviewOnly = true`, `notTradeInstruction = true`, and `manualReviewRequired = true`.

It cannot become executable point generation, order intent, execution intent, or auto-trading.

## INCOMPLETE Conditions

Future numeric point proposal must stay `INCOMPLETE` when any condition is true:

- `dataQualityContextId` missing;
- `dataQualityScore` missing;
- `dataQualityScore < 70`;
- `dataQualityGrade` unknown;
- `sourceTraceCompletenessScore` missing;
- `runtimeKlineCompletenessScore` missing;
- OHLCV completeness unknown;
- `freshnessScore` missing;
- source trace stale;
- runtime context stale;
- latestPrice/latestClose conflict unresolved;
- multi-timeframe consistency unknown;
- liquidity quality unknown;
- stampede risk unknown;
- wick confirmation missing;
- event risk unknown during active event window;
- abnormal data unknown;
- `missingFields` not empty;
- `riskActionGuardRef` missing;
- `degradedReasons` missing when score is degraded;
- `missingReason` absent when numeric value unavailable.

`INCOMPLETE` may explain unavailable quality context but must not generate numeric values.

## BLOCKED_FAIL_CLOSED Conditions

Future numeric point proposal must become `BLOCKED_FAIL_CLOSED` when any condition is true:

- `hardThresholdPassed = false`;
- source trace forged / untrusted;
- source trace attempts to bypass Risk Action Guard;
- `dataQualityScore` below hard threshold;
- severe OHLCV gap;
- confirmed stampede;
- severely degraded liquidity;
- confirmed abnormal data;
- blocking event risk;
- multi-timeframe conflict would induce immediate reverse;
- data quality context implies buy / sell / long / short;
- data quality context implies order intent;
- data quality context implies execution intent;
- data quality context implies auto-trading;
- external channel attempted before authorization.

`BLOCKED_FAIL_CLOSED` must never be rendered as a trade-ready numeric point.

## Risk Action Guard Integration

DataQuality cannot bypass Risk Action Guard.

Risk Action Guard ref must enter DataQuality context before future numeric point review.

High risk does not mean immediate stop.

High risk does not mean immediate reverse.

High risk does not mean immediate open.

Strong reversal does not mean direct reverse.

Wick / pin-bar behavior does not mean trend reversal.

Stampede state blocks opportunity push.

Degraded liquidity does not recommend one-shot market cutting.

Even complete DataQuality cannot become a trading action.

## Allowed Review-Only Output

P315 allows only planning-language output:

- DataQuality contract status;
- score missing reason;
- degraded review-only reason;
- threshold failure reason;
- source trace quality reason;
- runtime kline quality reason;
- OHLCV completeness reason;
- liquidity / stampede / wick / event / abnormal data quality reason;
- Risk Action Guard required reason;
- fixture matrix expectations;
- validator / contract PR prerequisites.

It does not allow numeric value generation.

## Final Conclusion

P315 moves the planning state from `RUNTIME_KLINE_CONTEXT_NUMERIC_POINT_CONTRACT_PLAN` to `DATA_QUALITY_NUMERIC_POINT_CONTRACT_PLAN`.

It defines the minimum DataQuality contract that future numeric point values must satisfy. It keeps all point work review-only, incomplete-safe, fail-closed, and blocked from executable trading semantics.
