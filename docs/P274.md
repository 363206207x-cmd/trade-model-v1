# P274 External Channel Disabled No-Op Java Skeleton

P274 is the disabled no-op external channel Java skeleton after P273.

P274 exists only to model whether a future external channel remains disabled. It does not connect Telegram, email, webhook, app notification, or local notification. It does not handle provider credentials, make live provider calls, render messages, generate final send text, send messages, activate schedulers, expose API/dashboard wiring, read runtime/live/external data, upgrade Readiness, generate point values, or create trading actions.

## Baseline

Current main before P274:

```text

```

P273 closed P272 and authorized only this disabled no-op Java skeleton. P273 did not authorize real external channel behavior, provider credentials, live provider calls, message rendering, message sending, scheduler/API/dashboard wiring, Readiness, point generation, order/execution, or auto-trading.

## Skeleton Contract

P274 must stay:

- disabled-by-default
- fail-closed
- audit-only
- review-only
- no-message
- no-provider-call
- no-credential
- no delivery attempt
- no scheduler/API/dashboard
- no runtime/live/external data
- no Readiness
- no point generation
- no entry/stop/TP/RR
- no order/execution/auto-trading

`OpportunityPushExternalChannelPolicy` may accept `OpportunityPushProviderChannelDTO` as input, but it must not call any external channel and must not send any message.

Missing, null, or unsafe provider channel input must fail closed. A non-disabled-noop provider channel remains incomplete, blocked, or disabled and can never connect to an external channel. A safe disabled-noop provider channel may only become a disabled no-op external channel result.

Reasons and blocking reasons must be preserved, and list fields must use defensive copies.

## Boundary Rules

P274 does not authorize:

- Telegram/email/webhook/app notification/local notification integration
- external channel behavior
- provider credential read/store/use
- live provider calls
- provider selection
- message rendering or final send text
- message sending
- scheduler/API/dashboard wiring
- schema/mapper/repository/DB write
- runtime/live/external data reads
- real scan loop
- external Opportunity Push execution
- Promote To Home runtime logic
- Readiness upgrade
- point generation
- real entry/stop/TP/RR
- order API
- execution API
- auto-trading

Display Slots / 默认六币 cannot become the batch universe or default push universe. Watchlist Pool remains the only push candidate boundary. Risk Action Guard must stay before any delivery path. Stampede state blocks opportunity push. A pin-bar/wick is not a trend reversal. A strong reversal is not direct reverse trading.
