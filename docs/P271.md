## 4. Future Provider Channel Scope

A future provider channel may only be introduced after separate authorization.

The first allowed shape must be a disabled no-op Java skeleton.

That future skeleton must start:

- disabled-by-default
- fail-closed
- audit-only
- review-only
- no-message-sending
- no-credential
- no-live-provider-call

The future provider channel may only represent provider eligibility or channel boundary metadata. It must not select a real provider, render final message text, send a message, read provider credentials, call Telegram / email / webhook / app notification / local notification, activate scheduler behavior, connect API / dashboard, read runtime / live / external data, upgrade Readiness, generate point levels, or create trading actions.
