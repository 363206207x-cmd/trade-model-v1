## V41-AUDIT-B01 - Opportunity Cooling And Timeframe Debounce

Result: `REMEDIATED`

- Opportunity state ownership and transition audit now include `timeframe`.
- Authoritative state identity and upsert uniqueness are `(symbol, timeframe)`.
- Opportunity IDs generated by the canonical state service include timeframe.
- `INVALIDATED -> COOLING` and `CONFUSED -> COOLING` are explicit recovery
  transitions and are not blocked by ordinary debounce.
- Active Cooling suppresses direct promotion to Candidate, Waiting Trigger, or
  Triggered until `cooling_until` expires.
- Suppressed evaluations do not move the state-entry timestamp or extend the
  cooling deadline.
- Transition audit continues to record from/to state, reason, trigger source,
  timestamp, analysis, trace, Opportunity, symbol, and timeframe.

Primary files:

- `AssetStateService.java`
- `AssetStateServiceImpl.java`
- `AssetStateMapper.java`
- `AssetStateDO.java`
- `OpportunityStateTransitionDO.java`
- `OpportunityStateTransitionMapper.java`
- `V11__fundamental_ai_v4_1_decision_chain.sql`

Regression evidence:

- Invalidated and Confused recovery to Cooling.
- Promotion suppression during active Cooling.
- Promotion after Cooling expiry.
- Independent debounce for the same symbol on `5m` and `1h`.

## V41-AUDIT-B03 - UserPosition Final Plan Association

Result: `REMEDIATED`

New writes require an explicit source:

- `SYSTEM_PLAN_POSITION` requires a validated `finalPlanId`.
- `MANUAL_POSITION` explicitly represents a position entered without a system
  plan and must not carry `finalPlanId`.

For a system-plan position, the referenced plan must be for the same symbol,
must be Final, and must have Rule Validation `PASS`. Historical `MANUAL` rows
are migrated to `MANUAL_POSITION`; read compatibility remains for historical
fixtures, while new persistence uses only canonical source values.

Primary files:

- `UserPositionSourceTypeEnum.java`
- `UserPositionSourceEnum.java`
- `UserPositionServiceImpl.java`
- `UserPositionMapper.java`
- `V11__fundamental_ai_v4_1_decision_chain.sql`

Regression evidence:

- System-plan position without Final plan is rejected.
- Cross-symbol, non-Final, and unvalidated plans are rejected.
- Explicit manual position without a plan is accepted.
- Manual position with a plan is rejected.
- Position Monitoring retains canonical source traceability.

## V41-AUDIT-B04 - Conflict Level 1-4 Alignment

Result: `REMEDIATED`

The v4.1 contract now uses only:

- `LEVEL_1_CONSISTENT`
- `LEVEL_2_MINOR_DISAGREEMENT`
- `LEVEL_3_SIGNIFICANT_DISAGREEMENT`
- `LEVEL_4_EXTREME_CONFLICT`

The AI role schema, Resolver output, persisted constraint, Dashboard label
mapping, Review reason mapping, and tests use the same canonical names. Level 4
sets Confused and forces `BLOCKED`; Levels 2 and 3 apply bounded plan-mode,
confidence, and risk downgrades without replacing the rule direction.

Primary files:

- `AiConflictLevelEnum.java`
- `AiDecisionChainSchema.java`
- `AiConflictResolverServiceImpl.java`
- `ReviewReasonsBuilder.java`
- `V11__fundamental_ai_v4_1_decision_chain.sql`

Regression evidence:

- All four levels are generated.
- Resolver output is canonical.
- Level 2 maps to bounded preparation.
- Level 3 maps to reduction.
- Level 4 maps to Confused and Blocked.
