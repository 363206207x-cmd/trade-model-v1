## WatchlistPoolProof Binding Boundary

WatchlistPoolProof is the proof layer for whether an asset is allowed to enter candidate / opportunity-push boundaries.

It is not a market scanning layer. It is not a push sending layer. It is not a trading layer.

It may carry only explicit input fields:

- SourceTrace refs;
- RuntimeKlineContext ref;
- DataQualityContext ref;
- MultiTimeframeContext ref;
- RiskActionGuardContext ref;
- Watchlist Pool ref and version;
- Watchlist Pool enabled / empty / membership states;
- membership source;
- membership observed / expiry timestamps;
- proof freshness / staleness states;
- Display Slot flags and refs;
- promoted-to-home review-only label;
- low-frequency-scan review-only label;
- audit / operator refs;
- membership / proof reasons;
- allowed / blocked candidate boundary labels;
- missing / degraded / blocked reasons.

It does not read watchlist configuration. It does not read service state. It does not read audit tables. It does not scan market data. It does not send messages. It does not generate actions or point values.

## Core Safety Rules

P342 fixes these WatchlistPoolProof semantics as review-only validation rules:

- Watchlist Pool is the maximum boundary for opportunity-push candidates;
- Display Slots / default home assets are not Watchlist Pool proof;
- default display on the home page does not authorize push candidacy;
- assets outside Watchlist Pool cannot enter opportunity-push candidates;
- disabled pool is `BLOCKED_FAIL_CLOSED`;
- empty pool is `BLOCKED_FAIL_CLOSED`;
- missing membership is `BLOCKED_FAIL_CLOSED`;
- stale or not-fresh proof cannot pass silently;
- untrusted source is `BLOCKED_FAIL_CLOSED`;
- promoted-to-home candidate is only review-only context;
- low-frequency scan candidate is only review-only context and not market-scan runtime;
- WatchlistPoolProof cannot manufacture SourceTrace refs or Watchlist membership.
