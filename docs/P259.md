# P259 Opportunity Push Closure and External Channel Gate Pack

## 1. 阶段定位

P259 是 P258 Opportunity Push Review-Only Skeleton 合并后的 docs-only closure and gate pack。

P259 只做收口和未来授权门定义，不写 Java，不修改 tests / DTO / dashboard / schema / config，不新增 controller / endpoint / API / mapper / service / scheduler，不连接任何外部通道，不发送任何消息。

## 4. Future External Channel Scope

未来 external push channel 可在另行授权后考虑：

- Telegram
- email
- webhook
- app notification
- local notification

P259 不实现这些通道，不新增 channel adapter，不新增配置，不新增发送器，不读取 runtime / live / external data，不接 MarketQuoteClient 或 BinanceMarketQuoteClient。

未来 delivery 必须另行定义 throttling / idempotency / audit requirements。P259 只记录这些要求，不实现节流、幂等或审计落库。

## 5. Candidate Boundary

Opportunity Push candidate 的最大候选边界只能来自 Watchlist Pool。

Display Slots（首页展示位）只是展示优先级，不是 batch universe。

默认六币不能作为 batch universe，也不能作为默认推送全集。

非 Watchlist Pool 资产不能进入 Opportunity Push 候选边界。

## 6. Delivery Safety Gate

未来任何 delivery 之前必须先通过 Risk Action Guard。

必须保持：

- `manualReviewRequired=true`
- `notTradeInstruction=true`
- no trading action
- no order / execution
- no entry / stop / TP / RR
- no Readiness upgrade
- watchlist-only candidate boundary

踩踏状态禁止机会推送。

插针不等于趋势反转。

强反转不等于直接反手。

## 7. Java Authorization

P259 不授权 Java implementation。

未来 P260 如需进入 push channel Java skeleton，必须另行授权，只能从安全骨架开始，且默认 fail-closed / disabled / review-only。

P260 也不得在没有额外授权时连接 Telegram / email / webhook / app notification / local notification，不得发送消息，不得接 scheduler / API / dashboard / MarketQuoteClient / BinanceMarketQuoteClient，不得生成交易路径。

## 8. 结论

P259 完成 P258 review-only Opportunity Push skeleton 的 docs-only closure，并定义 external channel / delivery safety / Java authorization / Readiness still-blocked gate。

P259 不提升 Push execution、Readiness 或 point generation 进度。
