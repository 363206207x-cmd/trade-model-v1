## 4. Future Delivery Pipeline Scope

A future delivery pipeline may only be considered after separate authorization.

That future work must start as:

- disabled-by-default
- fail-closed
- audit-only
- review-only
- no-message
- no-provider

The future delivery pipeline may only consume internal no-op / audit-only state and must not send messages, call external providers, activate scheduler behavior, create runtime queue behavior, change readiness, generate point levels, or create trading actions.
