# P306 Readiness / Point Boundary Planning Gate

## Purpose

P306 starts the Readiness / Point Mainline as a docs-only planning gate.

Its purpose is to define the boundary after the P299-P305 Candidate / Push review-only MVP chain and before any Readiness, point proposal, external channel, execution advice, or trading behavior.

P306 prevents the system from jumping directly from internal push preview to external push, point generation, or trade advice.

## Current Completed Upstream Chain

The upstream Candidate / Push review-only MVP chain is complete only as an internal, non-sendable preview loop:

- P299: `ReviewOnlyScoreAssemblyDTO` -> `ReviewOnlyCandidateHandoffDTO`.
- P300: `ReviewOnlyCandidateHandoffDTO` -> `ReviewOnlyCandidateAttentionDTO`.
- P301: `ReviewOnlyCandidateAttentionDTO` -> `ReviewOnlyCandidatePreviewGuardDTO`.
- P302: `ReviewOnlyCandidatePreviewGuardDTO` -> `ReviewOnlyInternalPushPreviewDTO`.
- P303: push preview closure before external channel.
- P304: dashboard / internal push preview display gate.
- P305: Candidate / Push review-only MVP closure.

This chain reaches dashboard-visible internal preview display only.

Candidate / Push review-only MVP closure does not mean the output is tradable, sendable, ready, ranked, or point-bearing.

## What P306 Is Not

P306 is not a Java implementation.

P306 is not a test package.

P306 is not a dashboard change.

P306 is not real Readiness.

P306 is not point generation.

P306 does not generate entry, stop, TP, RR, final direction, long-short signal, order intent, or execution intent.

P306 does not authorize external channel behavior.

P306 does not connect Telegram, email, webhook, app notification, local notification, `MarketQuoteClient`, `BinanceMarketQuoteClient`, or any runtime/live/external data reader.

Internal Push Preview is not external push.

External Channel requires a separate C-level authorization gate and cannot be reached directly from P306.

## Readiness Boundary

Readiness is not "this looks like an opportunity, therefore ready."

Future Review-only Readiness Gate work must fail closed unless the following boundaries are explicit:

- Candidate preview is still valid.
- Recheck has passed.
- Risk Action Guard has passed.
- Data quality is sufficient.
- Source trace is present and source-owned.
- Missing evidence has been classified through an incomplete gate.
- Multi-timeframe context meets the minimum consistency requirement.
- Liquidity is not deteriorating into a stampede state.
- The move is not merely a short wick or isolated pin bar.
- Event risk, black swan risk, and missing data have been surfaced.

Readiness can only be review-only until a future package explicitly changes that boundary. It must remain manual-review required and not a trade instruction.

## Point Boundary

Point Boundary work must not invent entry, stop, TP, or RR.

Future Review-only Point Proposal work may only enter the point boundary after Review-only Readiness Gate work exists.

Entry, stop, TP, and RR must come from source-owned trace and must expose the owning source, evidence context, freshness, and guard state.

If source trace, market context, data quality, structure confirmation, or multi-timeframe confirmation is missing, the point boundary must return `INCOMPLETE`.

Any point output must be a manual-review proposal, not a trade instruction, not an order intent, and not an executable signal.

## INCOMPLETE Rules

The future readiness / point chain must return `INCOMPLETE` when any required source or confirmation is absent.

Required incomplete cases include:

- Missing source trace.
- Missing market context.
- Missing data quality proof.
- Missing structure confirmation.
- Missing multi-timeframe confirmation.
- Missing liquidity context.
- Missing event-risk context.
- Missing Risk Action Guard result.
- Missing recheck result.

`INCOMPLETE` is a safe output. It prevents fabricated readiness, fabricated points, and unsupported trading advice.

## Risk Action Guard Integration

Risk Action Guard is a hard gate, not display copy.

Future readiness and point work must not bypass it.

Core rules:

- Strong reversal does not equal direct reverse.
- A wick or pin bar does not equal trend reversal.
- Stampede state forbids opportunity push, direct reverse, and new-position suggestions.
- High risk with normal liquidity may produce only manual-review suggestions such as reduce position, tighten stop, reduce leverage, or wait for confirmation.
- High risk with worsening liquidity must not suggest a one-shot market exit; it may only suggest staged de-risking, waiting for liquidity recovery, or lowering leverage.
- High risk with stampede prioritizes capital protection and forbids external push escalation.

Readiness / Point work must first remain a review-only gate before any external channel can be considered.

## Allowed Review-Only Outputs

P306 allows planning for future review-only outputs such as:

- readiness review-only status;
- incomplete reason;
- manual review required;
- point boundary unavailable reason;
- risk guard required reason;
- wait for recheck;
- wait for source trace;
- wait for market context;
- wait for Risk Action Guard.

These outputs must remain non-executable, manual-review required, and not trade instructions.

## Blocked Outputs

P306 blocks:

- executable entry;
- executable stop;
- executable TP;
- executable RR;
- real order instruction;
- order intent;
- execution intent;
- external push send;
- Telegram / email / webhook / app notification / local notification;
- final direction;
- long-short signal;
- auto-trading.
