# P323 Source-owned Numeric Point Candidate Assembler Plan

## Purpose

P323 belongs to the Readiness / Point Mainline.

P323 follows P322 `REVIEW_ONLY_NUMERIC_POINT_ASSEMBLER_JAVA_SKELETON`.

P323 defines the future Source-owned Numeric Point Candidate Assembler plan.

P323 is docs-only. It does not add Java, tests, DTOs, validators, assemblers, services, dashboard runtime integration, external channel, order, execution, or auto-trading.

The goal is to define how future source-owned contexts may be converted into explicit review-only numeric point proposal input while preserving `NumericPointSafetyValidator` as the final safety gate.

## Responsibility Boundary

The future Source-owned Numeric Point Candidate Assembler may only:

- select numeric fields that already exist in source-owned context;
- move source-owned numeric fields without calculation;
- bind source refs;
- bind runtime kline context refs;
- bind data quality context ref;
- bind multi-timeframe context ref;
- bind Risk Action Guard ref;
- bind Watchlist Pool proof;
- create review-only proposal input;
- call `ReviewOnlyNumericPointProposalAssembler`;
- let `NumericPointSafetyValidator` make the final safety decision.

The future Source-owned Numeric Point Candidate Assembler must not:

- calculate entry;
- calculate stop;
- calculate TP;
- calculate RR;
- derive entry from latestPrice;
- derive boundaries from latestClose;
- derive stop from volatility;
- derive TP from ATR or RR formulas;
- generate points from score, label, AI prose, dashboard text, or display copy;
- generate final direction;
- generate any trading action;
- send messages;
- call external APIs;
- read order, position, account, or execution paths;
- become a real strategy or order system.

## Difference From Existing Classes

`ReviewOnlyNumericPointProposalDTO` is the carrier.

`NumericPointSafetyValidator` is the safety gate.

`ReviewOnlyNumericPointProposalAssembler` is an explicit-field mover. It accepts explicit input, chooses the DTO factory, and immediately validates.

The future Source-owned Numeric Point Candidate Assembler would sit before that explicit-field mover. Its only job would be converting source-owned contexts into explicit assembler input.

It must not bypass `NumericPointSafetyValidator`.

It must not directly return executable points.

It must not bypass Risk Action Guard.

## Allowed Input Sources

Future inputs may only come from already-created source-owned context:

- SourceTrace numeric source;
- RuntimeKlineContext ref;
- DataQuality context;
- MultiTimeframe context;
- RiskActionGuard context;
- WatchlistPoolProof;
- explicit source-owned entry source;
- explicit source-owned stop source;
- explicit source-owned TP source;
- explicit source-owned RR source.

Each input must already carry a source ref or missing reason.

## Forbidden Input Sources

The future assembler must reject or mark incomplete any input derived from:

- latestPrice alone;
- latestClose alone;
- dashboard text;
- AI prose;
- score label;
- candidate label;
- conflict label;
- final decision text;
- manually invented fallback number;
- hardcoded default point;
- direct exchange order book read;
- direct MarketQuoteClient read;
- direct WebClient, RestTemplate, HttpClient, or OkHttp read;
- database write path;
- order, execution, or auto-trading path.

## Entry Candidate Rules

Entry candidate fields may only be moved from source-owned entry context:

- entryPrice;
- entryZoneLow;
- entryZoneHigh;
- entryTimeframe;
- entrySourceRef;
- entryMissingReason.

Entry candidate is not buy, long, open, or any other entry instruction.

Missing `entrySourceRef` must produce `INCOMPLETE`.

latestPrice-only entry source must produce `INCOMPLETE`.

Unresolved entry source conflict must produce `INCOMPLETE`.

Forged or untrusted entry source must produce `BLOCKED_FAIL_CLOSED`.

Executable semantics in entry output must produce `BLOCKED_FAIL_CLOSED`.

## Stop Candidate Rules

Stop candidate fields may only be moved from source-owned stop or invalidation context:

- stopPrice;
- stopZoneLow;
- stopZoneHigh;
- stopTimeframe;
- stopSourceRef;
- stopMissingReason.

Stop candidate is not a stop-loss order.

Stop candidate is not market close.

Stop candidate is not a one-shot market cut.

High risk does not mean immediate stop.

Degraded liquidity does not recommend a one-shot market cut.

Missing `stopSourceRef` must produce `INCOMPLETE`.

Forged or untrusted stop source must produce `BLOCKED_FAIL_CLOSED`.

Executable semantics in stop output must produce `BLOCKED_FAIL_CLOSED`.

## TP Candidate Rules

TP candidate fields may only be moved from source-owned TP context:

- takeProfitPrice;
- takeProfitZoneLow;
- takeProfitZoneHigh;
- takeProfitTimeframe;
- takeProfitSourceRef;
- takeProfitMissingReason.

TP candidate is not a take-profit order.

TP candidate is not a sendable order.

TP candidate is not automatic take-profit behavior.

Missing TP source may become degraded only when entry and stop are complete and a clear missing reason exists.

Forged or untrusted TP source must produce `BLOCKED_FAIL_CLOSED`.

Executable semantics in TP output must produce `BLOCKED_FAIL_CLOSED`.

## RR Candidate Rules

RR candidate fields may only be moved from source-owned RR context:

- riskRewardValue;
- riskRewardFormula;
- entrySourceRef;
- stopSourceRef;
- takeProfitSourceRef;
- calculationTrace;
- riskRewardMissingReason.

RR candidate is not an open condition.

RR candidate must not override Risk Action Guard.

Missing RR may become degraded only when an explicit missing reason exists.

Forged or untrusted RR source must produce `BLOCKED_FAIL_CLOSED`.

Executable semantics in RR output must produce `BLOCKED_FAIL_CLOSED`.

## Status Rules

### REVIEW_ONLY_NUMERIC_POINT_CANDIDATE

This status is allowed only when all of the following are true:

- entry source-owned context is complete;
- stop source-owned context is complete;
- TP source-owned context is complete;
- RR source-owned context is complete;
- SourceTrace refs are complete;
- RuntimeKlineContext refs are complete;
- DataQuality context exists;
- MultiTimeframe context exists;
- RiskActionGuard context exists;
- WatchlistPoolProof exists;
- `ReviewOnlyNumericPointProposalAssembler` is called;
- `NumericPointSafetyValidator` passes;
- all safety flags remain true.

This status is still review-only and not a trade instruction.

### REVIEW_ONLY_NUMERIC_POINT_DEGRADED

This status is allowed only when:

- entry and stop are complete;
- TP or RR is missing;
- the missing reason is explicit;
- no hard block exists;
- validator returns degraded;
- manual review and recheck remain required.

This status is not executable.

### INCOMPLETE

The future assembler must produce `INCOMPLETE` when:

- source-owned context is missing;
- entry source is missing;
- stop source is missing;
- TP source is missing and missing reason is absent;
- RR source is missing and missing reason is absent;
- SourceTrace refs are missing;
- RuntimeKlineContext refs are missing;
- DataQuality context is missing;
- MultiTimeframe context is missing;
- RiskActionGuard context is missing;
- WatchlistPoolProof is missing;
- only latestPrice exists;
- only score label exists;
- only AI prose exists;
- candidate source conflict is unresolved.

`INCOMPLETE` may explain what is missing, but it must not generate numeric point values.

### BLOCKED_FAIL_CLOSED

The future assembler must produce `BLOCKED_FAIL_CLOSED` when:

- source is forged or untrusted;
- Risk Action Guard is missing but candidate assembly is attempted;
- stampede is confirmed and opportunity candidate assembly is attempted;
- liquidity is severely degraded and executable output is attempted;
- strong reversal is treated as direct reverse;
- wick-only signal is treated as trend reversal;
- external channel is attempted;
- Push send is attempted;
- order intent is attempted;
- execution intent is attempted;
- auto-trading is attempted;
- forbidden executable semantics are detected;
- source-owned assembler bypasses validator.

`BLOCKED_FAIL_CLOSED` must never be rendered as trade-ready.
