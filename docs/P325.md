# P325 Source-owned Numeric Point Candidate Assembler Verification

## Purpose

P325 belongs to the Readiness / Point Mainline.

P325 follows P324 `SOURCE_OWNED_NUMERIC_POINT_CANDIDATE_ASSEMBLER_JAVA_SKELETON`.

P325 is docs-only verification for the P320-P324 review-only numeric point candidate chain.

It verifies what the chain can currently carry and check, what it still cannot do, and why it still cannot generate executable entry / stop / TP / RR.

P325 is not Java implementation, not testing implementation, not dashboard runtime integration, not external push, and not order / execution / auto-trading.

## Verified Chain

The current P320-P324 chain contains:

- `ReviewOnlyNumericPointProposalDTO`;
- `ReviewOnlyNumericPointProposalDTOTest`;
- `NumericPointSafetyValidator`;
- `NumericPointSafetyValidatorTest`;
- `ReviewOnlyNumericPointProposalAssembler`;
- `ReviewOnlyNumericPointProposalAssemblerTest`;
- `SourceOwnedNumericPointCandidateAssembler`;
- `SourceOwnedNumericPointCandidateAssemblerTest`.

The chain is a review-only candidate container, safety validator, explicit-field assembler, and source-owned-field assembler.

It does not include source context production, service wiring, dashboard runtime wiring, external channels, or trading execution.

## DTO Layer Verification

`ReviewOnlyNumericPointProposalDTO` only carries review-only candidate data.

It supports:

- `INCOMPLETE`;
- `BLOCKED_FAIL_CLOSED`;
- `REVIEW_ONLY_NUMERIC_POINT_CANDIDATE`;
- `REVIEW_ONLY_NUMERIC_POINT_DEGRADED`.

The DTO keeps safety flags forced true:

- `reviewOnly`;
- `notTradeInstruction`;
- `manualReviewRequired`;
- `recheckRequired`;
- `riskActionGuardRequired`;
- `sourceTraceRequired`;
- `runtimeKlineContextRequired`;
- `dataQualityRequired`;
- `multiTimeframeRequired`;
- `incompleteSafe`.

When status is `BLOCKED_FAIL_CLOSED`, `failClosed` remains true.

Entry, stop, TP, and RR are nullable review-only fields. They are not trading instructions.

The DTO does not calculate point values.

The DTO does not derive values from latest price, score labels, candidate labels, AI prose, dashboard text, or market data.

## Validator Layer Verification

`NumericPointSafetyValidator` is the safety gate for the DTO.

It verifies:

- required safety flags;
- `sourceTraceRefs`;
- `runtimeKlineContextRefs`;
- `dataQualityContextRef`;
- `multiTimeframeContextRef`;
- `riskActionGuardRef`;
- `watchlistPoolProof`;
- entry / stop / TP / RR presence by status;
- missing reasons for incomplete or degraded output;
- blocked reasons for fail-closed output;
- forbidden executable semantics.

It can output:

- `INCOMPLETE`;
- `BLOCKED_FAIL_CLOSED`;
- `REVIEW_ONLY_NUMERIC_POINT_CANDIDATE`;
- `REVIEW_ONLY_NUMERIC_POINT_DEGRADED`.

The validator does not calculate point values.

The validator does not call service, controller, mapper, repository, scheduler, runtime provider, MarketQuoteClient, BinanceMarketQuoteClient, WebClient, RestTemplate, HttpClient, OkHttp, DataSource, external channel, push send, order, execution, or auto-trading paths.

## Explicit Assembler Layer Verification

`ReviewOnlyNumericPointProposalAssembler` is an explicit-field mover.

It:

- accepts explicit assembly input;
- maps requested status to DTO factories;
- returns proposal plus validation result;
- calls `NumericPointSafetyValidator` after every assembly;
- preserves explicitly supplied BigDecimal point fields without calculation.

It does not calculate entry, stop, TP, RR, final direction, long / short signal, or executable action.

It does not infer values from latest price, latest close, volatility, score labels, candidate labels, AI prose, dashboard text, or market data.

It does not call service, controller, external channel, push send, order, execution, or auto-trading paths.

## Source-owned Candidate Assembler Layer Verification

`SourceOwnedNumericPointCandidateAssembler` converts source-owned context to `ReviewOnlyNumericPointProposalAssembler.AssemblyInput`.

It then calls `ReviewOnlyNumericPointProposalAssembler`, so `NumericPointSafetyValidator` remains mandatory.

It verifies the intended boundary:

- source-owned entry / stop / TP / RR contexts are moved only when already present;
- entry / stop / TP / RR source refs or missing reasons remain required by status;
- `trustedSource = false` becomes `BLOCKED_FAIL_CLOSED` with `SOURCE_UNTRUSTED`;
- missing entry or stop source refs remain `INCOMPLETE`;
- missing TP or RR with explicit missing reason may become degraded review-only;
- missing TP or RR without explicit missing reason remains `INCOMPLETE`;
- forbidden executable semantics become `BLOCKED_FAIL_CLOSED`.

It does not calculate point values.

It does not infer values from latest price, latest close, volatility, ATR, RR formula, score labels, candidate labels, AI prose, dashboard text, or market data.

It does not call service, dashboard runtime, external channel, push send, order, execution, or auto-trading paths.

After P325, the system still cannot generate real executable entry / stop / TP / RR.

More precisely:

- Java skeletons can carry and validate review-only candidate point fields;

- real runtime kline context is not connected;
