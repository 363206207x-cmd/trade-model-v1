# P326 Source Context Integration Plan

## Purpose

P326 belongs to the Readiness / Point Mainline.

P326 follows P325 `SOURCE_OWNED_NUMERIC_POINT_CANDIDATE_ASSEMBLER_VERIFICATION`.

P326 is a docs-only plan for future real source context integration into the review-only numeric point candidate chain.

It defines which upstream contexts must exist before the current DTO / validator / assembler skeletons can receive real source-owned entry / stop / TP / RR candidate inputs.

P326 is not Java, not tests, not service wiring, not dashboard runtime integration, not external push, and not order / execution / auto-trading.

## Responsibility Boundary

Source context integration is the future bridge from real upstream evidence to the current review-only numeric candidate chain.

It may define how upstream contexts should be produced, referenced, checked, and passed into `SourceOwnedNumericPointCandidateAssembler`.

It must not:

- calculate entry;
- calculate stop;
- calculate TP;
- calculate RR;
- infer values from latest price or latest close;
- infer values from score labels, candidate labels, AI prose, or dashboard text;
- connect MarketQuoteClient, BinanceMarketQuoteClient, WebClient, RestTemplate, HttpClient, OkHttp, DataSource, or external providers;
- connect service runtime, dashboard runtime, external channel, Push send, order, execution, or auto-trading.

`SourceTraceNumericSourceContext` is the source identity for entry / stop / TP / RR.

Future integration must provide:

- `sourceTraceId`;
- `sourceOwner`;
- `sourceType`;
- `symbol`;
- `market`;
- `timeframe`;
- `numericFieldName`;
- `numericValue`;
- `numericValueLow`;
- `numericValueHigh`;
- `observedAt`;
- `freshnessStatus`;
- `sourceConfidence`;
- `sourceRef`;
- `missingReason`;
- `blockedReason`.

Rules:

- missing `sourceTraceId` -> `INCOMPLETE`;
- missing `sourceRef` -> `INCOMPLETE`;
- stale source -> `INCOMPLETE`;
- forged or untrusted source -> `BLOCKED_FAIL_CLOSED`;
- symbol / timeframe / market mismatch -> `INCOMPLETE`;
- source that induces executable trade semantics -> `BLOCKED_FAIL_CLOSED`;
- source must not come from AI prose, dashboard text, score label, candidate label, manually invented fallback, hardcoded default, or latest-price-only input.

## RiskActionGuardContext Integration

`RiskActionGuardContext` is an action safety gate, not a score field.

Future integration must provide:

- `riskActionGuardContextId`;
- `overallRiskLevel`;
- `liquidityState`;
- `liquiditySeverity`;
- `stampedeState`;
- `wickStatus`;
- `wickConfirmationStatus`;
- `strongReversalStatus`;
- `strongReversalConfirmationStatus`;
- `highTimeframeConflictStatus`;
- `allowedReviewOnlyActions`;
- `forbiddenActions`;
- `manualReviewRequired`;
- `notTradeInstruction`;
- `reviewOnly`;
- `missingReason`;
- `blockedReason`.

Core rules:

- high risk does not mean immediate stop;
- high risk does not mean immediate reverse;
- high risk does not mean immediate open;
- strong reversal does not mean direct reverse;
- wick does not mean trend reversal;
- stampede state blocks opportunity push;
- degraded liquidity does not support one-shot market cutting.

Rules:

- missing `RiskActionGuardContext` -> `INCOMPLETE`;
- `manualReviewRequired = false` -> `BLOCKED_FAIL_CLOSED`;
- `notTradeInstruction = false` -> `BLOCKED_FAIL_CLOSED`;
- `reviewOnly = false` -> `BLOCKED_FAIL_CLOSED`;
- stampede confirmed -> `BLOCKED_FAIL_CLOSED`;
- strong reversal treated as direct reverse -> `BLOCKED_FAIL_CLOSED`;
- wick-only treated as trend reversal -> `BLOCKED_FAIL_CLOSED`.
