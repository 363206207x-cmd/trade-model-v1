# P312 Source-owned Numeric Point Proposal Plan

## Purpose

P312 belongs to the Readiness / Point Mainline.

It is a docs-only plan after P311 `EXECUTABLE_POINT_GENERATION_PRE_APPROVAL_PLAN`.

P312 defines the future shape of a source-owned review-only numeric point proposal. It does not create Java files, does not generate real point values, and does not connect dashboard, API, external channel, order, execution, or auto-trading.

## Current Upstream Boundary

P311 defined that any future numeric point proposal must first pass:

- SourceTrace completeness;
- RuntimeKlineContext completeness;
- DataQuality gate;
- multi-timeframe confirmation;
- Liquidity / Stampede / Wick / StrongReversal Risk Action Guard;
- manual review.

P312 uses that boundary to define the planned object semantics only.

## Future Object Boundary

The future object may be named `ReviewOnlyNumericPointProposalDTO`.

P312 does not create this Java object.

The future object boundary is:

- input: a review-only point proposal display / closure context that has passed pre-approval planning;
- output: source-owned numeric point proposal fields for human review only;
- status: `REVIEW_ONLY_NUMERIC_POINT_PROPOSAL`, `INCOMPLETE`, or `BLOCKED_FAIL_CLOSED`;
- execution surface: none.

The object must always keep:

- `reviewOnly = true`
- `notTradeInstruction = true`
- `manualReviewRequired = true`
- `recheckRequired = true`
- `riskActionGuardRequired = true`
- `sourceTraceRequired = true`
- `runtimeKlineContextRequired = true`
- `incompleteSafe = true`
- `failClosed = true` when blocked

## What P312 Is Not

P312 is docs-only.

P312 does not raise Production Runtime Progress.

P312 does not mean a Java DTO is complete.

P312 does not mean numeric point proposal is implemented.

P312 does not mean real entry / stop / TP / RR are complete.

P312 does not mean dashboard runtime integration.

P312 does not mean external push.

P312 does not mean order, execution, or auto-trading.

P312 does not allow direct order placement after merge.

## Entry / Entry Zone Fields

Future entry planning must include these nullable fields:

| Field | Meaning | Required source trace |
|---|---|---|
| `entryType` | Review-only type such as boundary, pullback, breakout-retest, invalidation-adjacent, or unavailable. | entry source trace |
| `entryPrice` | Nullable numeric review-only entry value. | entry numeric source trace |
| `entryZoneLow` | Nullable lower bound of a review-only entry zone. | entry zone source trace |
| `entryZoneHigh` | Nullable upper bound of a review-only entry zone. | entry zone source trace |
| `entryTimeframe` | Timeframe that owns the entry source. | entry timeframe trace |
| `entrySourceType` | Source class such as structure, support, resistance, pullback, or boundary. | entry source trace |
| `entrySourceRef` | Stable source reference. | entry source trace |
| `entrySourceReason` | Human-readable reason without trade instruction wording. | entry source trace |
| `entryObservedAt` | Observation time of the source. | entry source trace |
| `entryFreshnessStatus` | Fresh / stale / unknown source freshness. | entry source trace |
| `entryConfidenceForReviewOnly` | Review-only confidence label or score, not an execution score. | entry source plus data quality trace |
| `entryInvalidIf` | Review-only invalidation condition, not a stop order. | entry and stop source traces |
| `entryMissingReason` | Required when entry is null or incomplete. | incomplete reason trace |

Entry is not buy, long, open, or an order instruction.

## Nullable Fields

The following future fields must remain nullable:

- `entryPrice`
- `entryZoneLow`
- `entryZoneHigh`
- `stopPrice`
- `stopZoneLow`
- `stopZoneHigh`
- `tpPrice`
- `tpZoneLow`
- `tpZoneHigh`
- `tpReviewOnlyAllocationRatio`
- `rrValue`
- all source refs when the matching source is missing
- all observed-at timestamps when source context is incomplete
- all confidence and freshness fields when source quality is unknown

When a required nullable field is missing, the object must include the matching missing reason and remain `INCOMPLETE`.

## Forbidden Instruction Interpretation

The following must never be inferred from the object:

- buy;
- sell;
- long;
- short;
- open long;
- open short;
- close position;
- reverse;
- order intent;
- execution intent;
- auto-trading.

Entry / stop / TP / RR values, if future packages add them, are review-only source-owned proposal fields. They are not executable commands.

## INCOMPLETE Rules

Future numeric point proposal must remain `INCOMPLETE` when any of these are true:

- entry source missing;
- stop source missing;
- TP source missing;
- RR source missing;
- source trace stale;
- runtime kline context missing;
- data quality below threshold;
- timeframe conflict;
- liquidity unknown;
- stampede unknown;
- wick unconfirmed;
- strong reversal unconfirmed;
- Risk Action Guard not executed;
- manual review missing;
- watchlistPoolProof missing;
- any required numeric source is inferred from display text;
- any point value is fabricated from score, label, or latest price only.

`INCOMPLETE` may expose missing reasons but must not invent numeric values.

## BLOCKED_FAIL_CLOSED Rules

Future numeric point proposal must become `BLOCKED_FAIL_CLOSED` when any of these are true:

- proposed output implies buy / sell / long / short;
- proposed output implies order intent;
- proposed output implies execution intent;
- proposed output implies auto-trading;
- Risk Action Guard failed;
- stampede confirmed;
- liquidity severely degraded;
- source trace forged;
- data quality hard threshold failed;
- numeric proposal attempts to bypass manual review;
- external channel attempted before authorization.

`BLOCKED_FAIL_CLOSED` must not downgrade into hidden executable behavior.

## Review-Only Numeric Proposal But Still Not Executable

A future package may enter review-only numeric proposal only when:

- all required source traces are present and fresh enough;
- runtime kline context is present;
- data quality passes the configured threshold;
- multi-timeframe confirmation does not conflict;
- liquidity and stampede states are known and safe enough for review;
- wick and strong-reversal conditions have Risk Action Guard review;
- manual review remains required;
- output remains not a trade instruction.

Even then, the object cannot place, close, reverse, resize, execute, externally send, or auto-trade.

## Risk Action Guard Relationship

Risk Action Guard must run before numeric point generation.

The following rules remain mandatory:

- high risk does not mean immediate stop;
- high risk does not mean immediate reverse;
- high risk does not mean immediate open;
- strong reversal does not mean direct reverse;
- wick / pin-bar behavior does not mean trend reversal;
- stampede state blocks opportunity push;
- degraded liquidity should not produce a one-shot market-cut suggestion;
- even review-only numeric points cannot become trading actions.
